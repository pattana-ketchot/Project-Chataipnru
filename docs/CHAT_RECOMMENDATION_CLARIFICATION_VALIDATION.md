## 1. วิธีวัด

เรียก **เฉพาะขั้นจำแนกเจตนา** ด้วยพรอมต์และคอนฟิกของ production ตัวจริง (`RECOMMEND_INTENT_SYSTEM_PROMPT`, `gemini-3.5-flash-lite`, `temperature=0.0`, `json_mode`) จากในคอนเทนเนอร์ backend ที่รันอยู่ — **1 คำขอต่อข้อความ รวม 3 คำขอ ตามเพดานที่อนุมัติ**

- ไม่เรียก `/api/chat` และไม่เรียก `match_programs` จึงไม่มีผลการจัดอันดับมาเกี่ยวข้องกับข้อสรุป
- ค่า "interest ที่โค้ดจะใช้จริง" คำนวณในเครื่องจากผลดิบชุดเดียวกัน โดยทำตามตรรกะ `chat.py:544–552` ทุกบรรทัด ไม่ได้เรียกโมเดลซ้ำ
- session ฐานข้อมูลใช้อ่านชื่อหลักสูตรอย่างเดียว และปิดด้วย `rollback()`

## 2. ผลดิบจากโมเดล

| # | ข้อความ | คำตอบดิบของโมเดล | is_recommendation | `interest` ดิบ |
|---|---|---|---|---|
| 1 | เรียนไรดี | `{"recommendation": true, "interest": ""}` | true | **ว่าง** |
| 2 | แนะนำสาขาหน่อย | `{"recommendation": true, "interest": ""}` | true | **ว่าง** |
| 3 | ชอบเขียนโปรแกรม เรียนอะไรดี | `{"recommendation": true, "interest": "ชอบเขียนโปรแกรม"}` | true | `ชอบเขียนโปรแกรม` |

## 3. สิ่งที่โค้ดปัจจุบันทำต่อจากนั้น

| # | interest เป็นข้อความย่อยของคำถามไหม | ข้อความที่ถูกส่งเข้า `match_programs` จริง |
|---|---|---|
| 1 | ไม่ (ว่าง) | **`"เรียนไรดี"` ทั้งประโยค** |
| 2 | ไม่ (ว่าง) | **`"แนะนำสาขาหน่อย"` ทั้งประโยค** |
| 3 | ใช่ | `"ชอบเขียนโปรแกรม"` |

ยืนยันสมมติฐานใน RCA ครบถ้วน: โมเดลบอกอย่างถูกต้องว่า "ไม่มีความสนใจให้คัด" (`interest = ""`) แต่ `chat.py:545` แทนที่ค่าว่างนั้นด้วยข้อความทั้งประโยค แล้วเดินหน้าจัดอันดับต่อ สัญญาณที่จำเป็นมีอยู่แล้วและถูกทิ้งไป

ทั้ง 3 ข้อความถูกจัดเป็น recommendation ทั้งหมด ซึ่งตรงตามพรอมต์ — ปัญหาจึงไม่ได้อยู่ที่การจำแนกเจตนา แต่อยู่ที่การไม่ใช้ค่า `interest` ว่างเป็นเงื่อนไข

## 4. ข้อเสนอ implementation (ยังไม่ทำ รออนุมัติ)

ตรงกับ Primary Approach ใน RCA และใช้ได้ทันทีเพราะสัญญาณเชื่อถือได้

**จุดแก้ 2 แห่งใน `backend/app/services/chat.py` ไฟล์เดียว**
1. `_recommendation_intent` — แยก "ขอคำแนะนำแต่ไม่มีความสนใจ" ออกจาก "ไม่ใช่การขอคำแนะนำ" แทนการแทนค่าว่างด้วยทั้งประโยค (คืนค่าที่บอกสถานะได้ เช่น ค่าคงที่ `NO_PREFERENCE` แทนการคืนสตริง)
2. ด่าน 0.72 ใน `prepare_answer` (บรรทัด ~1147) — เมื่อได้สถานะนั้น ตอบด้วยข้อความถามกลับคงที่ **โดยไม่เรียก `match_programs`**

**ข้อความถามกลับ** ต้องขึ้นต้นด้วย `_FOLLOW_UP_LEAD` เดิม เพื่อให้เทิร์นถัดไปเข้าเส้นทาง `_refinement_of_recommendation` ที่มีอยู่แล้ว และควรบอกทางเลือกว่าขอดูรายชื่อสาขาทั้งหมดก็ได้ (`asks_for_program_list` มีอยู่แล้ว)

**ไม่แตะ:** สูตรคะแนน, `_RELEVANCE_MARGIN 0.04`, `limit=3`, embeddings/retrieval, Gemini rationale, prompt/model/config, RAG, Structured Answers, Find Major, frontend, DB

**Offline tests ที่ต้องเพิ่ม** (ดักด้วย spy ว่ามีการเรียก `match_programs` หรือไม่)
1. `interest` ว่าง → ได้ข้อความถามกลับ และ `match_programs` ต้องไม่ถูกเรียก
2. `interest` มีเนื้อหา → จัดอันดับเหมือนเดิมทุกตัวอักษร
3. ข้อความถามกลับต้องมี `_FOLLOW_UP_LEAD`
4. เทิร์นถัดไปหลังถูกถามกลับ ตอบว่า "ชอบเขียนโปรแกรม" → ต้องได้คำแนะนำจริง
5. คำถามข้อเท็จจริง / รายชื่อสาขา / ค่าเทอม ต้องไม่ถูก gate นี้แตะ
6. ชุดเดิม 350 tests ต้องผ่าน

**ความเสี่ยงที่เหลือ:** วัดได้ 1 ตัวอย่างต่อข้อความ ครอบคลุม 3 สำนวน การรับประกันว่าโมเดลคืนค่าว่างกับทุกสำนวนที่ไม่มีความสนใจยังทำไม่ได้ แต่ผลที่แย่ที่สุดของการพลาดคือ "ถามกลับทั้งที่ผู้ใช้บอกความสนใจมาแล้ว" ซึ่งกู้คืนได้ในเทิร์นถัดไป และเสียหายน้อยกว่าการแนะนำโดยไม่มีหลักฐาน · ไม่จำเป็นต้องใช้เกณฑ์คะแนนขั้นต่ำในรอบนี้
