## 2. Field ที่ `/api/chat` ส่งกลับมาจริง

ทดสอบยิงจริง 3 คำถาม ดูทั้ง header และ body

**Body:** `Content-Type: text/plain; charset=utf-8` — เป็นข้อความคำตอบล้วน ๆ แบบ stream
**ไม่ใช่ JSON** จึงไม่มี field ใด ๆ ใน body

**Header ที่ได้จริง:**

| Header | เมื่อไหร่ที่ส่ง | ตัวอย่างค่า |
|---|---|---|
| `X-Accel-Buffering` | ทุกครั้ง | `no` |
| `X-Source-Document` | **เฉพาะคำตอบที่มาจากเอกสารจริง** | `7e06cd12-87ee-49ab-9687-c5dc51114474` |
| `X-Source-Page` | เฉพาะเมื่อมีเลขหน้าเป็นจำนวนเต็มบวก | `3` |

**ผลการทดสอบจริง:**

| คำถาม | ได้ source header ไหม |
|---|---|
| "หลักสูตรวิทยาการคอมพิวเตอร์เรียนกี่หน่วยกิต" | ❌ ไม่ได้ |
| "ปรัชญาของหลักสูตรวิทยาการคอมพิวเตอร์คืออะไร" | ❌ ไม่ได้ |
| "เรียนวิทยาการคอมพิวเตอร์จบแล้วทำงานอะไรได้บ้าง" | ✅ `X-Source-Document` + `X-Source-Page: 3` |

โค้ดฝั่ง backend ที่กำหนดเรื่องนี้คือ `backend/app/api/routes/web_compat.py:106 _source_headers()`
ซึ่งเขียนคอมเมนต์ไว้ชัดว่า "ส่งเฉพาะเมื่อรู้เอกสารจริงเท่านั้น ไม่มี document_id ก็ไม่ส่งอะไรเลย
ห้ามเดาหรือส่งค่าว่าง" — **ตรงกับ requirement ข้อ 1 ที่ว่าถ้าไม่มี source จริงก็ไม่ต้องแสดงปุ่ม**

### ⚠️ เจอของเสียระหว่างตรวจ

`src/pages/ChatAdvisor.jsx:71` อ่าน header ชื่อ **`X-RAG-Sources`** เพื่อเอามาทำชิป "อ้างอิงจาก:"
แต่ backend **ไม่เคยส่ง header ชื่อนี้เลย** (ยิงจริง 3 ครั้ง ไม่มีสักครั้ง)
`X-RAG-Sources` เป็นของระบบเพื่อน ส่วน `/api/chat` วิ่งเข้า FastAPI ของเราซึ่งส่ง
`X-Source-Document`/`X-Source-Page` แทน

**แปลว่าชิป "อ้างอิงจาก:" ในหน้าแชทไม่เคยขึ้นเลยบน production** — เป็นโค้ดตายมาตั้งแต่ merge
ไม่ใช่ของที่ผมเพิ่งทำพัง แต่ควรแก้ไปพร้อมงานนี้

## 3. สรุป: ทำได้แค่ไหนด้วยของที่มีอยู่

| Action | ทำได้เลยไหม | ติดอะไร |
|---|---|---|
| 1️⃣ 📄 ดูเอกสารหลักสูตร | **ได้บางส่วน** | มี `X-Source-Document` + `X-Source-Page` และ `/api/documents/{id}/pdf` ใช้งานได้จริง (ตรวจแล้ว 200, `cs66.pdf`) **แต่ไม่มี "ชื่อเอกสาร"** — chat ส่งมาแค่ id ส่วนชื่อไฟล์อยู่ใน `Content-Disposition` ของ endpoint PDF เท่านั้น |
| 2️⃣ 🎓 ดูรายละเอียดสาขา | **ยังไม่ได้** | คำตอบจาก `/api/chat` **ไม่มี course id และไม่มีชื่อสาขา** เป็น field ใด ๆ เลย |
| 3️⃣ 🌐 เว็บไซต์สาขา PNRU | **ได้ ถ้ารู้ว่าเป็นสาขาไหน** | URL ครบ 12 สาขาแล้ว (ตาราง ข้อ 1) แต่ยังติดปัญหาเดียวกับข้อ 2 คือไม่รู้ว่าคำตอบพูดถึงสาขาไหน |
| 4️⃣ 🏫 เว็บไซต์คณะ | **ได้เลย** | เป็น URL เดียวคงที่ `https://sci.pnru.ac.th` ตรวจแล้ว 200 |

**ปัญหาแกนกลาง:** ปุ่ม 2 และ 3 ต้องรู้ว่า "คำตอบนี้พูดถึงสาขาไหน"
ซึ่ง `/api/chat` ไม่ได้บอกมา ผมจึง**ไม่เดา** และไม่ทำ matching จากข้อความคำตอบ
เพราะ requirement ระบุว่า "ห้ามสร้าง document ID หรือ source ขึ้นเอง"

## 4. แผนว่าจะเพิ่ม UI ตรงไหน

**ไฟล์:** `src/pages/ChatAdvisor.jsx`
**ตำแหน่ง:** ใต้ message bubble ของ assistant — ที่เดิมของชิป "อ้างอิงจาก:" (บรรทัด ~220–239)

**โครงที่ตั้งใจใช้ (responsive ตามที่สั่ง):**

```

│ 🌐 เว็บไซต์สาขา PNRU        │   ≥1024px: แถวเดียว 4 ปุ่ม
├────────────────────────────┤
│ 🏫 เว็บไซต์คณะ              │
└────────────────────────────┘
```

- ปุ่มภายใน (1, 2) ใช้ `<Link>` ของ react-router
- ปุ่มภายนอก (3, 4) ใช้ `<a target="_blank" rel="noopener noreferrer">`
- ปุ่มไหนไม่มีข้อมูลจริง **ไม่แสดงปุ่มนั้น** ไม่แสดงปุ่มที่กดแล้วพัง
- ถ้าไม่มีปุ่มเลยสักอัน ไม่แสดงกล่อง "ข้อมูลเพิ่มเติม"
- ใช้ `flex-wrap` + `min-w-0` + `break-words` กัน horizontal overflow
- จะทดสอบครบ 360/390/430/768/820/1024/1280 เหมือนรอบ responsive

## 5. ต้องแก้ Backend ไหม

**ต้อง — ถ้าอยากได้ปุ่มที่ 2 และ 3 ให้ทำงานจริง** มีทางเลือก 3 แบบ เรียงจากกระทบน้อยไปมาก

### ทางเลือก A — เพิ่ม 2 header ใน `/chat-web` (แนะนำ)
เพิ่มใน `_source_headers()` ให้ส่ง `X-Source-Title` (ชื่อไฟล์เอกสาร) และ
`X-Source-Programme` (ชื่อสาขาตามเอกสาร) เมื่อรู้จริงเท่านั้น

- ✅ ไม่เปลี่ยน API contract เดิม (เพิ่ม header ใหม่ ของเก่าไม่กระทบ)
- ✅ ไม่แตะ schema ไม่แตะ RAG ไม่แตะ scoring
- ✅ ข้อมูลมีอยู่แล้วใน `course_documents` ที่ endpoint PDF query อยู่
- ⚠️ ต้องแก้ไฟล์ backend และ deploy ใหม่ → **รอการอนุมัติ**

### ทางเลือก B — frontend map เอง ไม่แตะ backend เลย
เก็บ mapping `ชื่อสาขา → {courseId, pnruUrl}` เป็นไฟล์ค่าคงที่ในฝั่ง frontend
แล้วจับคู่กับ **ชื่อสาขาที่ปรากฏในข้อความคำตอบ**

- ✅ ไม่แตะ backend, ไม่แตะ database เลย
- ❌ ต้องเดาจากข้อความคำตอบ ซึ่งขัดกับ "ห้ามสร้าง source ขึ้นเอง"
- ❌ คำตอบที่พูดถึงหลายสาขาจะเลือกผิดได้
- **ผมไม่แนะนำ** แต่ทำได้เร็วที่สุดถ้าอยากได้ทันวันพรีเซนต์

### ทางเลือก C — เพิ่มคอลัมน์ใน Supabase
เพิ่มคอลัมน์ `pnru_url` ในตาราง `courses`

- ❌ เป็น schema ของเพื่อน และ**ตอนนี้ติดต่อเพื่อนไม่ได้** + เราไม่มีสิทธิ์ admin/editor
- ❌ ขัดกับที่สั่งไว้ว่า "ยังไม่แก้ database/schema"
- **ไม่แนะนำในตอนนี้**

### วิธีเก็บ mapping ที่กระทบระบบน้อยที่สุด
ไม่ว่าเลือกทางไหน ตาราง URL 12 สาขาควรเก็บเป็น **ไฟล์ค่าคงที่ในฝั่ง frontend**
เช่น `src/data/programmeLinks.js` เพราะ

- ไม่ต้องแก้ schema ของใคร ไม่ต้องขอสิทธิ์ Supabase
- อยู่ใน git ตรวจสอบย้อนหลังได้ว่าใครแก้ URL เมื่อไหร่
- คณะเปลี่ยน URL เมื่อไหร่ แก้ไฟล์เดียวจบ
- ผูกกับ **course id จริง** ไม่ใช่ชื่อสาขา จึงไม่พังเวลาชื่อสาขาเปลี่ยน

## 6. ขอการตัดสินใจ 3 ข้อ

1. **เลือกทาง A, B หรือ C** สำหรับปุ่มที่ 2 และ 3
   (ถ้าเลือก A ผมต้องแก้ backend + deploy ซึ่งต้องได้รับอนุมัติก่อน)
2. **ให้ query `course_documents` เพื่อเติม PDF ครบ 12 สาขาไหม** — เป็นการอ่านอย่างเดียว ไม่เขียน
3. **แก้ชิป "อ้างอิงจาก:" ที่ตายอยู่ไหม** (เปลี่ยนจาก `X-RAG-Sources` ไปอ่าน
   `X-Source-Document`) — เป็นการแก้ frontend อย่างเดียว

**ยังไม่ลงมือส่วนที่กระทบ API/Database จนกว่าจะได้รับอนุมัติ**
