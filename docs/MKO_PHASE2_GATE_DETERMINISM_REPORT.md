# MKO Phase 2 — ทำให้ด่านตรวจของคำถามเปรียบเทียบตัดสินได้แน่นอน (ข้อ 6)

## 1. Root cause

ใน Controlled Model Validation ข้อ 6 ("วิทยาการคอมพิวเตอร์กับเทคโนโลยีสารสนเทศ สาขาไหนเรียนเขียนโปรแกรมมากกว่ากัน")
ถูกรันสองครั้ง ได้หลักฐานชุดเดียวกัน แต่ด่านตรวจตอบต่างกัน ครั้งหนึ่งผ่าน อีกครั้งไม่ผ่าน (1/2)

- ด่านตรวจของคำถามหลายหลักสูตร (`_can_answer_from` + `GROUNDING_COMPARISON_SYSTEM_PROMPT`) ให้ Gemini ตัดสินใจทุกกรณี
- คำถามเชิงปริมาณ ("มากกว่ากัน") ทำให้โมเดลลังเล ว่าต้องมีตัวเลขครบก่อนถึงจะผ่าน หรือแค่มีข้อเท็จจริงของทุกหลักสูตรก็พอ
- ดังนั้นผลผ่าน/ไม่ผ่านจึงสุ่มตามโมเดล ทั้งที่คำถามเดิมและหลักฐานเดิม

ส่วนที่ตัดสินได้จากหลักฐานจริงว่า "มีเนื้อหาของทุกหลักสูตรในเรื่องที่ถามไหม" จึงไม่ควรปล่อยให้โมเดลตัดสิน
ส่วนเรื่อง "จัดอันดับได้ไหม" เป็นหน้าที่ของขั้นเขียนคำตอบ ซึ่งมีกฎบังคับให้ตอบว่ายังสรุปไม่ได้

## 2. Logic ที่เปลี่ยน

ไฟล์ `backend/app/services/comparison_evidence.py` มีฟังก์ชันใหม่ `comparison_support(question, programmes, chunks)`
ฟังก์ชันนี้ใช้เฉพาะคำถามที่เอ่ยถึงหลายหลักสูตร และตัดสินจากชิ้นเนื้อหาที่ส่งจริงเท่านั้น
คำถามเดิมกับหลักฐานเดิมจะได้ผลเดิมทุกครั้ง

ตัดสินตามลำดับนี้ หยุดที่ข้อแรกที่เข้าเงื่อนไข:

| ลำดับ | เงื่อนไข | ผล |
|---|---|---|
| 1 | มีหลักสูตรที่ไม่มีชิ้นเนื้อหาที่ใช้ได้เลย (ไม่นับสารบัญ/ชิ้นอ่านไม่ออก) | `MISSING_PROGRAMME` → not_found ทันที |
| 2 | คำถามตรง field ที่มีหัวข้อตามแบบ มคอ.2 (อาชีพ / วัตถุประสงค์ / หน่วยกิตรวม) | ถ้าพบหัวข้อนั้นครบทุกหลักสูตร → `SUPPORTED` ถ้าไม่ครบ → `UNDETERMINED` |
| 3 | ตัดชื่อหลักสูตร ปี และคำที่ใช้ถามออกแล้วไม่เหลือเรื่องที่ถาม และคำถามขอจัดอันดับ | `UNDETERMINED` |
| 4 | ไม่เหลือเรื่องที่ถาม (เช่น "ต่างกันอย่างไร") | ถ้ามีหัวข้ออย่างน้อยหนึ่งด้านที่ครบทุกหลักสูตร → `SUPPORTED` ถ้าไม่มี → `UNDETERMINED` |
| 5 | เรื่องที่ถามสั้นเกินจะตรวจด้วยข้อความ (ไทย < 3 ตัวอักษรหลัก, อังกฤษ < 2 ตัว) | `UNDETERMINED` |
| 6 | พบข้อความของเรื่องที่ถามในเนื้อหาของทุกหลักสูตร | `SUPPORTED` ถ้าไม่ครบ → `UNDETERMINED` |

ใน `chat.prepare_answer` (หลังด่าน off-topic เดิม):

- `MISSING_PROGRAMME` → not_found โดยไม่เรียกโมเดล
- `SUPPORTED` → ผ่านโดยไม่เรียก LLM gate และเพิ่มบรรทัด `[สรุปจากระบบ: ...]` ในหมายเหตุหลักฐาน
  - ถ้าคำถามขอจัดอันดับ (มากกว่า / น้อยกว่า / เยอะกว่า / ที่สุด / กว่ากัน) จะเพิ่มอีกบรรทัดที่บอกขั้นเขียนคำตอบว่า
    ระบบไม่ได้นับหรือจัดอันดับให้ ให้จัดอันดับได้เฉพาะเมื่อมีตัวเลขหรือรายการครบที่เทียบกันได้ตรงๆ
  - ถ้าไม่ถึงขั้นนั้น ให้ตอบว่ายังสรุปไม่ได้ พร้อมยกข้อเท็จจริงของทุกหลักสูตรและบอกเกณฑ์ที่ต้องกำหนดก่อน
- `UNDETERMINED` → ใช้ LLM gate เดิม (grounding คงไว้สำหรับกรณีที่โค้ดตัดสินไม่ได้)
- คำถามหลักสูตรเดียวไม่เปลี่ยน

ไม่มีชื่อหลักสูตรหรือประโยคทดสอบในโค้ด:
- ชื่อหลักสูตรมาจาก `resolve_scopes`
- เรื่องที่ถามได้จากการตัดคำทั่วไปของการถามเปรียบเทียบออก (`_QUESTION_WORDS`)
- field ใช้ `_FIELD_PATTERNS` เดิมของ `structured_intent`

## 8. ข้อจำกัดที่ยังเหลือ

1. **`UNDETERMINED` ยังใช้ LLM gate เดิม** ความไม่นิ่งยังเกิดได้เฉพาะในกรณีนี้ เช่น คำถามที่ใช้คำคนละคำกับเอกสาร หรือเรื่องที่ถามสั้นเกินจะตรวจด้วยข้อความ
2. **การหาเรื่องที่ถามเป็นการตัดคำทั่วไปของการถามออก** ไม่รู้คำพ้องความหมาย
   - เช่น ถาม "coding" แต่เอกสารเขียน "เขียนโปรแกรม" จะเป็น `UNDETERMINED` แล้วไปใช้ LLM gate
   - ไม่ผ่านผิดๆ เพราะต้องพบข้อความในเนื้อหาของทุกหลักสูตร
3. **`SUPPORTED` แปลว่า "มีเนื้อหาของเรื่องที่ถามครบทุกหลักสูตร" ไม่ใช่ "ตอบคำถามจัดอันดับได้"**
   - การไม่จัดอันดับอาศัยกฎของขั้นเขียนคำตอบ ซึ่งยังเป็นโมเดล
   - ใน 6 คำตอบจัดอันดับที่ทดสอบ ทำตามครบ แต่ไม่ใช่การรับประกันจากโค้ด
4. **ความลึกของคำตอบต่างกันแต่ละรอบ** (บางรอบยกรายวิชา บางรอบยกหมวดวิชาเฉพาะ 94 หน่วยกิต) และรอบ 3 ใช้เวลาเขียนคำตอบ 37.6 วินาที
5. **คำสะกดผิดจากโมเดล** (ข้อ 6) ยังเกิดได้ ไม่มีการตรวจตัวสะกดหลังเขียน
6. **ตัวกรองสารบัญเดิม (`_looks_like_table_of_contents`)** อาจตัดตารางรายวิชาที่มีตัวเลขหนาแน่นทิ้ง ทำให้หลักฐานน้อยลงได้
7. **ผลโมเดลวัดจากตัวอย่างน้อย** (ข้อ 6 ห้ารอบ) ส่วนที่ deterministic คือการตัดสินผ่าน/ไม่ผ่าน ไม่ใช่ถ้อยคำคำตอบ
