### 2.3 ข้อที่ตรวจแล้วพบว่า **ไม่ใช่ปัญหา**

> รอบแรกผมสรุปผิดว่า "ปุ่มเปิดเอกสารต้นฉบับไม่เคยทำงาน" เพราะคำถามสี่ข้อแรกไม่มี `X-Source-*` กลับมา

ที่จริงระบบส่ง header **เฉพาะเมื่อรู้เอกสารจริง** ซึ่งเป็นพฤติกรรมที่ออกแบบไว้ คำถามที่ตรงกับข้อมูลที่เผยแพร่แล้ว (อาชีพของวิทยาการคอมพิวเตอร์) ได้ header ครบและเปิด PDF ได้จริง — **ฟีเจอร์นี้ใช้งานได้ และเป็นจุดแข็งที่ควรโชว์**

## 3. จัดลำดับงาน

### ข้อ 1 — ทำให้เส้นทางพรีใช้งานไม่ได้

| # | อาการ | สาเหตุที่ยืนยันแล้ว | สถานะ |
|---|---|---|---|
| **1.1** | หน้า `/careers` ขึ้น "ยังไม่มีข้อมูลหลักสูตร" ทั้งที่มี 12 หลักสูตร | คอลัมน์ `careers` ของฐานข้อมูลหน้าเว็บ **เป็น `{}` ว่างทั้ง 12 แถว** (ยืนยันด้วยการอ่าน PostgREST ในนาม `anon` แบบเดียวกับที่หน้าเว็บทำ) ส่วนรายการอาชีพที่ตรวจกับเอกสารแล้วอยู่ที่หลังบ้าน ซึ่งหน้านั้นไม่เคยเรียก | **แก้แล้ว** |
| **1.2** | วินิจฉัยข้อ 1.1 จากหน้าเว็บไม่ได้เลย | `const { data } = await supabase…` ทิ้ง `error` ไป | **แก้แล้ว** |

> `db/migrations/005_web_schema.sql` บันทึกไว้แล้วว่า `careers = '{}' (ว่าง) = 12` ตอนทำ schema ตาม ดังนั้นช่องว่างนี้ **รู้อยู่แล้ว** แต่ยังไม่มีใครต่อหน้าเว็บเข้ากับข้อมูลที่มี

**ไม่พบข้ออื่นที่ทำให้เส้นทางที่ระบุใช้งานไม่ได้** — login/สิทธิ์ · จัดการหลักสูตร · การให้คำแนะนำ · AI/RAG · SCI Connect · หน้าที่บอกว่ากำลังพัฒนา ผ่านทั้งหมดตามข้อ 2

## 5. แผน deploy และ rollback

> **แผนฉบับใช้งานพร้อมคำสั่งที่คัดลอกได้อยู่ใน `docs/CAREERS_DEPLOY_2569-10-11.md`**
> ข้อนี้เป็นสรุประดับแนวคิด · **ถ้าสองที่ไม่ตรงกัน ให้ยึดไฟล์นั้น** ซึ่งแก้ `GET /api/chat` เป็น `POST` พร้อม body
> และระบุพาธจริงของ `/srv/web` แล้ว
>
> **ยังไม่ลงมือ** · ต้องอนุมัติก่อน · สองส่วนนี้แยกกันได้และย้อนแยกกันได้

### 5.1 สองส่วนที่ต้อง deploy

| ส่วน | เปลี่ยนอะไร | ถ้า deploy แค่ส่วนเดียว |
|---|---|---|
| **A** backend (FastAPI) | เพิ่มเส้นทาง `GET /career-lists` **ไม่แก้เส้นทางเดิมเลย** | ปลอดภัย — ไม่มีใครเรียกเส้นทางใหม่ ระบบเหมือนเดิมทุกอย่าง |
| **B** หน้าเว็บ (LastProject → โฟลเดอร์ `web/` บน host ที่ mount เป็น `/srv/web`) | หน้า "อาชีพหลังจบ" + แท็บข่าวสารของผู้ดูแล + ชื่อแท็บ | หน้าเว็บจะเรียก `/career-lists` แล้วได้ `404` → `fetch` ไม่ throw แต่ `res.ok` เป็น false → **แสดงหลักสูตรครบ 12 โดยไม่มีรายการอาชีพ** ไม่ล้ม |

> **ต้อง deploy A ก่อน B** · ถ้าสลับลำดับ ระบบไม่ล้ม แค่หน้ายังไม่มีรายการอาชีพจนกว่า A จะขึ้น

### 5.2 ก่อนลงมือ — ของสำรอง

| # | สิ่งที่ต้องสำรอง | วิธี |
|---|---|---|
| 1 | image ของ backend ที่ใช้อยู่ | `docker tag <image ปัจจุบัน> course-advisor-backend:pre-careers` แล้ว **จดบันทึก image ID** |
| 2 | ไฟล์หน้าเว็บที่เสิร์ฟอยู่ | คัดลอกโฟลเดอร์ `web/` **บน host** ไปที่ `/home/ubuntu/web-backup-2569-10-11/` |
| 3 | `web_compat.py` ฉบับก่อนแก้ | มีใน git แล้ว — commit `427ce19` |

### 5.3 ลำดับ deploy

| # | ขั้น | ตรวจอะไร |
|---|---|---|
| A1 | คัดลอก `backend/app/api/routes/web_compat.py` ขึ้นเซิร์ฟเวอร์ | ขนาดไฟล์ตรง |
| A2 | build image backend ใหม่ | สำเร็จ |
| A3 | ตรวจไฟล์ **ในคอนเทนเนอร์** ว่าเป็นฉบับใหม่ | `grep -c career-lists` ได้ ≥ 1 |
| A4 | `up -d --no-deps --no-build --force-recreate backend` | คอนเทนเนอร์ `healthy` · **image ID เปลี่ยน** |
| A5 | `GET /api/openapi.json` | มี `/career-lists` ในรายการ |
| A6 | **`POST /api/chat` พร้อม body จริง** ด้วยคำถามเดิมหนึ่งข้อ | ยัง `200` และคำตอบยังเป็นคำตอบจริง |
| B1 | `npm run build` ของ LastProject | สำเร็จ |
| B2 | คัดลอก `dist/` ไปโฟลเดอร์ `web/` **บน host** (ไม่ใช่ใน container — mount เป็น `:ro`) | ไฟล์ครบ |
| B3 | เปิด `/careers` | เห็นรายการอาชีพของหลักสูตรที่เผยแพร่แล้ว + ที่มา |

> **A3 สำคัญ** — scp แล้ว restart ไม่พอ ถ้า image ไม่ถูก build ใหม่จะยังรันโค้ดเก่าโดยที่คำสั่งขึ้นสำเร็จ

### 5.4 ตรวจหลัง deploy

| # | ทดสอบ | ต้องได้ |
|---|---|---|
| **V1** | `GET /api/career-lists` | `200` · มี `programmes` · ทุกรายการมี `source.file` |
| **V2** | นับจำนวนหลักสูตรที่ได้มา | **คาด 2** — ถ้าได้ 0 ให้ดูว่า `item_type='career'` ใน `v_live_list_items` มีแถวไหม |
| **V3** | เปิด `/careers` ด้วยตา | หลักสูตรที่มีรายการขึ้นก่อน · ที่ยังไม่มีขึ้นข้อความบอกตรงๆ · ไม่มีลิงก์เอกสารที่กดแล้ว 404 |
| V4 | **`POST /api/chat` พร้อม body จริง** คำถามอาชีพ CS | ยังได้ `X-Source-*` ครบเหมือนก่อน deploy |
| V5 | `/api/sci-connect-news` · `/api/recommend-major` · `/api/compare-courses` | ยัง `200` เหมือนเดิม |

### 5.5 Rollback

| ส่วน | วิธี | เมื่อไร |
|---|---|---|
| **B** หน้าเว็บ | คืนโฟลเดอร์ `web/` บน host จาก `/home/ubuntu/web-backup-2569-10-11/` | หน้า `/careers` เพี้ยน หรือหน้าอื่นพัง |
| **A** backend | `docker tag course-advisor-backend:pre-careers-2569-10-11 <backend.image ที่ compose ใช้>` แล้ว `up -d --no-deps --no-build --force-recreate backend` · **เทียบ image ID ก่อนและหลัง** | `/api/chat` หรือเส้นทางเดิมใดได้ผลต่างจากก่อน deploy |

**ลำดับย้อน: B แล้ว A** — ย้อน B ก่อนทำให้ไม่มีใครเรียกเส้นทางใหม่ แล้วย้อน A ได้อย่างปลอดภัย

**ย้อนแค่ A ได้ไหม** — ได้ · หน้าเว็บจะได้ `404` จาก `/career-lists` แล้วแสดงหลักสูตรครบโดยไม่มีรายการอาชีพ ไม่ล้ม

### 5.6 สิ่งที่ไม่ต้องย้อน

| รายการ | เหตุผล |
|---|---|
| ชื่อแท็บเบราว์เซอร์ | เปลี่ยนข้อความเท่านั้น ไม่มีผลต่อการทำงาน |
| ชุดทดสอบที่เพิ่ม | อยู่ในเครื่องพัฒนา ไม่ได้ขึ้น production |

## 7. ยืนยันขอบเขต

| ข้อห้าม | สถานะ |
|---|---|
| Deploy | **ไม่ได้ทำ** |
| เปลี่ยน production (ฐานข้อมูล · secret · cron · policy) | **ไม่ได้ทำ** |
| แตะงาน C1 / C2 | **ไม่ได้ทำ** — ไม่แก้ policy ไม่แก้ cron ไม่แก้ `webapi/api/` |
| รายงานว่า C3 ผ่าน production | **ไม่ได้ทำ** — C3 ยังเป็น patch ที่ไม่ได้ deploy |
| Push / Merge git | **ไม่ได้ทำ** |
| เพิ่มฟีเจอร์จากการคาดเดา | **ไม่ได้ทำ** — ใช้ข้อมูลที่ตรวจและเผยแพร่แล้วเท่านั้น |
| แสดงค่าคีย์ / token / ข้อมูลส่วนบุคคล | **ไม่มีในเอกสารนี้** |
