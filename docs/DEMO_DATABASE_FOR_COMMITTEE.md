# เปิดฐานข้อมูลให้กรรมการดู — วิธีทำและจุดที่ต้องแคปรูป

อัปเดต 23 กันยายน 2569

---

## 1. เปิดยังไง

เซิร์ฟเวอร์มี **Adminer** ติดตั้งไว้แล้วตั้งแต่ 14 ก.ย. รันอยู่ที่ `127.0.0.1:18081`
ผูกกับ localhost เท่านั้น **ไม่ได้เปิดออกอินเทอร์เน็ต** ซึ่งถูกต้องด้านความปลอดภัย
ส่วน PostgreSQL เองไม่ได้ publish port ออกนอก Docker จึงต่อตรงจากข้างนอกไม่ได้

### ขั้นตอน

**1) เปิดอุโมงค์ SSH** (รันทิ้งไว้ ไม่ต้องปิดหน้าต่าง)

```bash
ssh -i ~/.ssh/oci.key -N -L 18081:127.0.0.1:18081 ubuntu@161.118.237.37
```

**2) เปิดเบราว์เซอร์ไปที่**

```
http://127.0.0.1:18081
```

**3) หน้า login ของ Adminer กรอก**

| ช่อง | ค่า |
|---|---|
| System | PostgreSQL |
| Server | `postgres` |
| Username | ดูใน `.env` บนเซิร์ฟเวอร์ (`POSTGRES_USER`) |
| Password | ดูใน `.env` บนเซิร์ฟเวอร์ |
| Database | ดูใน `.env` บนเซิร์ฟเวอร์ (`POSTGRES_DB`) |

ทดสอบแล้วว่าอุโมงค์ทำงาน เปิดหน้า login ได้จริง

---

## ⚠️ ข้อควรระวัง 3 ข้อ — อ่านก่อนวันพรี

**1. อย่า login ต่อหน้ากรรมการ**
การกรอกรหัสผ่านบนจอโปรเจกเตอร์คือการเปิดเผยรหัสฐานข้อมูลให้ทั้งห้องเห็น
**ให้ login ไว้ก่อนเข้าห้อง** แล้วเปิดแท็บค้างไว้ พอถึงเวลาก็สลับแท็บไปเลย

**2. Adminer แก้ข้อมูลได้**
ถ้ากรรมการขอลองกดเอง มีโอกาสกดปุ่มลบหรือแก้โดยไม่ตั้งใจ
แนะนำให้**เราเป็นคนกดเอง** และเปิดเฉพาะหน้าที่เตรียมไว้

**3. ต้องมีเน็ต**
อุโมงค์ SSH ต้องต่อเซิร์ฟเวอร์ได้ ถ้าเน็ตห้องพรีมีปัญหาจะเปิดไม่ได้เลย
**ให้แคปรูปเก็บไว้ล่วงหน้าทุกหน้าตามรายการข้างล่าง** แล้วใส่เป็นสไลด์สำรอง

## 2. ต้องแคปรูปตรงไหนบ้าง — 6 รูป เรียงตามลำดับที่ควรโชว์

### รูปที่ 1 — รายการตารางทั้งหมด
**ไปที่:** หน้าแรกหลัง login → เลือก schema `public` แล้วแคป → สลับไป schema `mko` แล้วแคปอีกรูป
**พิสูจน์:** ระบบมีตารางจริง 28 ตาราง ไม่ใช่แค่ไฟล์ JSON
**จุดที่ต้องให้เห็นในรูป:** ชื่อตารางกับจำนวนแถว โดยเฉพาะ `course_chunks` 9,039 แถว

### รูปที่ 2 — โครงสร้างตาราง `course_chunks`
**ไปที่:** public → `course_chunks` → แท็บ Structure
**พิสูจน์:** เก็บเวกเตอร์จริง
**จุดที่ต้องให้เห็น:** คอลัมน์ `embedding` ชนิด **`vector(1024)`** ← วงกลมไว้เลย

### รูปที่ 3 — ดัชนีเวกเตอร์
**ไปที่:** หน้าเดียวกัน เลื่อนลงไปส่วน Indexes
**พิสูจน์:** ค้นด้วย vector index จริง ไม่ได้ไล่เทียบทีละแถว
**จุดที่ต้องให้เห็น:** ดัชนีชนิด **ivfflat** และ `vector_cosine_ops`

### รูปที่ 4 — โซ่หลักฐาน ⭐ รูปที่สำคัญที่สุด
**ไปที่:** เมนู SQL command แล้ววางคำสั่งนี้

```sql
SELECT c.title                                     AS "สาขา",
       fv.field_key                                AS "ข้อมูล",
       COALESCE(fv.value_text, fv.value_int::text) AS "ค่าที่สกัดได้",
       d.original_filename                         AS "เอกสารต้นฉบับ",
       ev.page_start                               AS "หน้า",
       fv.status                                   AS "สถานะตรวจทาน"
FROM mko.field_values fv
JOIN mko.evidence ev    ON ev.id = fv.evidence_id
JOIN course_documents d ON d.id  = ev.document_id
JOIN courses c          ON c.id  = d.course_id
WHERE COALESCE(fv.value_text, fv.value_int::text) IS NOT NULL
ORDER BY c.title, fv.field_key
LIMIT 12;
```

**พิสูจน์:** ทุกค่าที่ระบบใช้ตอบ **สาวกลับไปถึงเอกสารและเลขหน้าได้** และมีสถานะตรวจทานกำกับ
นี่คือสิ่งที่ทำให้งานเราต่างจากการต่อ API เฉย ๆ

ผลจริงที่ได้ (ทดสอบแล้ว):

| สาขา | ข้อมูล | ค่าที่สกัดได้ | เอกสาร | หน้า | สถานะ |
|---|---|---|---|---|---|
| การแพทย์แผนไทยประยุกต์ (2560) | degree_name_en | Bachelor of Applied Thai Traditional Medicine | attm.pdf | 6 | candidate |
| การแพทย์แผนไทยประยุกต์ (2560) | edition_year | 2560 | attm.pdf | 6 | **verified** |
| การแพทย์แผนไทยประยุกต์ (2560) | degree_abbr_th | พทป.บ. | attm.pdf | 6 | candidate |

### รูปที่ 5 — วิวข้อมูลที่เผยแพร่แล้ว
**ไปที่:** mko → `v_live_values` → Select data
**พิสูจน์:** ระบบตอบจากข้อมูลที่ผ่านการตรวจแล้วเท่านั้น (103 ค่า) ไม่ได้ตอบจากข้อมูลร่าง

### รูปที่ 6 — ตารางความสัมพันธ์
**ไปที่:** public → `course_documents` → Structure → ดูส่วน Foreign keys
**พิสูจน์:** มีคีย์นอกจริง เอกสารผูกกับหลักสูตร
**จุดที่ต้องให้เห็น:** `course_id` → `courses.id`

## 3. ถ้าไม่อยากเปิด Adminel เลย — ทางเลือกที่ปลอดภัยกว่า

ใช้ของที่มีอยู่แล้วแทน ไม่ต้องต่อเน็ต ไม่ต้องกรอกรหัสผ่าน

1. **ER Diagram** ที่ทำไว้แล้วใน `docs/database/` — `er_postgres_a_documents`, `er_postgres_b_metadata`, `er_supabase`
2. **พจนานุกรมข้อมูล 35 ตาราง** ในเล่มรายงานหัวข้อ 3.13
3. **6 รูปข้างบนที่แคปไว้ล่วงหน้า** ใส่เป็นสไลด์สำรองท้ายเล่ม

**แนะนำ:** แคปรูปไว้ล่วงหน้าทั้ง 6 รูปเป็นหลัก แล้วเปิด Adminer จริงไว้เป็นทางเลือก
ถ้ากรรมการขอดูสด ค่อยสลับแท็บ — ได้ทั้งความปลอดภัยและความน่าเชื่อถือ
