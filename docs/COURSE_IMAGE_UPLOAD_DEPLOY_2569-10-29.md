### 6.2 ที่ยังตรวจไม่ได้ และเหตุผล

ขั้นที่ 1–6 ของข้อ 6.4 ในแผน (เลือกรูป → ดูตัวอย่าง → ยังไม่บันทึกแล้วดูหน้าสาธารณะ →
บันทึก → ดูอีกครั้ง → คืนรูปเดิม) **ต้องเข้าสู่ระบบเป็นผู้ดูแลของ production**

ผมไม่ได้ทำสองอย่างนี้โดยตั้งใจ

* **ไม่ได้สวมบัญชีผู้ดูแลของคนอื่น** — การออก token ของผู้ใช้จริงเพื่อแก้ข้อมูลหลักสูตร
  บนของจริงเป็นการกระทำในนามคนอื่น ซึ่งไม่ได้รับมอบไว้
* **ไม่ได้อ่านตารางผู้ใช้ของ production** เพื่อหาบัญชีผู้ดูแล

สิ่งที่ทดแทนไว้แล้ว: เส้นทางเดียวกันนี้ **ทดสอบจบครบแล้วบนฐานทดสอบ** ด้วยไฟล์ชุดเดียวกัน
(hash ตรงกับที่ deploy) — ยิงผ่าน HTTP จริง 20 จุดตรวจ และกดผ่านฟอร์มแอดมินจริงในเบราว์เซอร์
ทั้งกรณีผ่านและกรณีที่ต้องไม่ผ่าน (ดูข้อ 3 ของเอกสาร readiness)

### 6.3 ขั้นที่ต้องทำเองก่อนถือว่าปิดงานครบ

1. เข้าหน้าแอดมิน → แก้หลักสูตรสักหลักสูตร (หรือสร้างหลักสูตรทดสอบ)
2. ช่องต้องขึ้นว่า **"รูปประจำสาขา"** พร้อมปุ่ม `เลือกรูปจากคอมพิวเตอร์`
3. เลือกรูป JPG/PNG/WebP ขนาดปกติ → URL ต้องเติมให้เอง และตัวอย่างรูปต้องขึ้น
4. **ยังไม่กดบันทึก** แล้วเปิดหน้าสาธารณะของหลักสูตรนั้น → รูปต้องยังเป็นรูปเดิม
5. กดบันทึก → เปิดหน้าสาธารณะอีกครั้ง → รูปเปลี่ยนเป็นรูปใหม่ · เปิด URL ของรูปตรง ๆ ต้องได้ 200
6. ลองเลือกไฟล์ PDF และไฟล์เกิน 5 MB → ต้องขึ้นข้อความบอกเหตุ และ URL เดิมต้องไม่เปลี่ยน
7. **คืนรูปเดิม** (วาง URL เดิมกลับแล้วบันทึก) ถ้าทดสอบกับหลักสูตรจริง
8. เปิดหน้า "ตั้งค่า AI" ของผู้ดูแล → ต้องเหมือนเดิม

ถ้าข้อใดไม่ผ่าน ให้ย้อนตามข้อ 7 แล้วบอกผม — ไฟล์ที่อัปโหลดไปแล้วไม่ต้องลบ เพราะรุ่นเก่า
เปิดไฟล์เหล่านั้นได้ปกติ

## 7. rollback

```bash
cd ~/course-advisor-system && docker compose \
  $(docker inspect -f '{{index .Config.Labels "com.docker.compose.project.config_files"}}' \
    course-advisor-system-backend-1 | tr ',' '\n' | grep -v image-upload | sed 's#^#-f #' | tr '\n' ' ') \
  -f ~/release-image-upload-2569-10-29/compose.rollback-backend-public-choice.yml \
  up -d --no-build --no-deps backend
```

**หน้าเว็บ** — ย้อน `index.html` กลับ bundle เดิม

```bash
cd ~/release-image-upload-2569-10-29 && ./rollback_web.sh --run \
  ~/release-image-upload-2569-10-29/web-run-20261029-072316
```

ย้อนฝั่งเดียวได้ทั้งคู่ — หน้าเว็บเก่าไม่มีปุ่มอัปโหลดแต่ backend ใหม่รับคำขอเดิมได้ปกติ
