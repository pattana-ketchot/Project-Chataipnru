## 2. ตรวจรับบนเว็บจริง (bundle ที่หน้านั้นโหลด: `index-DFnQ0dE2.js`)

### 2.1 โท–เอก ชื่อเดียวกัน — จุดที่เสี่ยงที่สุด

ทั้งสองแถวบนเว็บ **ไม่มี `course_id`** การจับคู่จึงอาศัย `level` ที่หน้าเว็บส่งไป

| คอลัมน์ | ปีและแหล่งอ้างอิงที่แสดง | ลิงก์เอกสาร |
|---|---|---|
| (ปริญญาโท) การจัดการเทคโนโลยีการเกษตรฯ | `ฉบับ พ.ศ. 2568` · **วิทยาศาสตรมหาบัณฑิต** · `agri68_master.pdf` | `/api/documents/51265845…/pdf` |
| (ปริญญาเอก) การจัดการเทคโนโลยีการเกษตรฯ | `ฉบับ พ.ศ. 2568` · **ปรัชญาดุษฎีบัณฑิต** · `agri68_phd.pdf` | `/api/documents/d1c84418…/pdf` |

## 4. ที่ยังไม่ได้ทำ / ข้อจำกัดที่ยังอยู่

* **แถวบนเว็บทั้ง 14 แถวยังไม่มี `course_id` เลยสักแถว** — ระบบทนได้แล้วเพราะใช้ `level`
  กับชื่อที่มีคำว่า "(ปริญญาโท)/(ปริญญาเอก)" แต่การเติม `course_id` ให้ถูกต้องจะแม่นขึ้นอีกชั้น
  และเป็นงานข้อมูล ไม่ใช่งานโค้ด
* กล่องตารางเลื่อนทั้งสองแกนในตัวเองแล้ว (จำเป็นสำหรับการตรึงหัว) หน้าจึงมีแถบเลื่อนของ
  ตารางแยกจากแถบเลื่อนของหน้า — ต่างจากเดิม
* ไม่มีชุดทดสอบอัตโนมัติของ `/course-facts` · รอบนี้ยืนยันด้วยการยิง API จริงบนฐานทดสอบ
  12 กรณี และตรวจรับบนเว็บจริงอีกชั้น
* ไม่มีหลักสูตรใดในระบบที่มี "เฉพาะฉบับย่อ" กรณีป้าย `ดูเอกสาร (ฉบับย่อ)` จึงตรวจด้วย
  ข้อมูลจำลองเท่านั้น
* commit หน้าเว็บยัง push ขึ้น GitHub ไม่ได้ (สิทธิ์) — มี `git bundle` ที่ clone กลับมาทดสอบแล้ว
