## 6. การทดสอบเข้าสู่ระบบ — เจ้าของทำเอง

**ไม่ขอรหัสผ่านในแชต** และไม่ได้ตั้งรหัสให้ใคร

บัญชีที่ย้ายมาใหม่ 2 บัญชี (`66*****@365.pnru.ac.th` และ `66*****@pnru.ac.th`) เป็น `password_scheme = bcrypt`
ถ้าเข้าสู่ระบบด้วย **รหัสผ่านเดิมที่ใช้กับ Supabase** ได้สำเร็จ แปลว่าการย้ายรหัสผ่านทำงาน

ยิงทดสอบได้ตรง ๆ โดยไม่ต้องรอขั้น E (หน้าเว็บปัจจุบันยังเรียก Supabase อยู่)

```bash
read -rp 'อีเมล: ' E && read -rsp 'รหัสผ่าน: ' P && echo && printf '{"email":"%s","password":"%s"}' "$E" "$P" > /tmp/login.json && curl -s -o /tmp/login.out -w 'HTTP %{http_code}\n' -X POST -H 'Content-Type: application/json' --data-binary @/tmp/login.json https://stpnru-advisor.duckdns.org/api/auth/login && head -c 120 /tmp/login.out && rm -f /tmp/login.json /tmp/login.out && unset P
```

| ได้ | แปลว่า |
|---|---|
| **200** พร้อม `access_token` | รหัสผ่านเดิมใช้ได้ · ระบบจะอัปเกรด `password_scheme` เป็น `bcrypt_sha256` ให้เอง |
| **401** | รหัสผ่านไม่ตรง (หรือเป็นบัญชีที่สมัครผ่าน OAuth ซึ่งไม่มีรหัสผ่าน) |
| **429** | ใส่ผิดหลายครั้งจนถูกจำกัด — รอแล้วลองใหม่ |

บอกผมแค่ผลลัพธ์ (ไม่ต้องบอกรหัส) แล้วผมจะตรวจจากฝั่งฐานข้อมูลว่า `password_scheme` เปลี่ยนเองไหม และมีแถวใน `auth_sessions` เพิ่มขึ้นไหม
