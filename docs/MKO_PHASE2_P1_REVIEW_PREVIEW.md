decision ที่จะบันทึกเป็น human review ต้องได้รับการยืนยันจากผู้อนุมัติ และต้องระบุชื่อผู้ตรวจที่จะบันทึก (`reviewed_by = human:<ชื่อ>`)

## วิธีตรวจ

1. **ยืนยันว่าเป็นไฟล์เดียวกับที่ระบบสกัด:** SHA-256 ของไฟล์ใน `samples/` ตรงกับ `public.course_documents.file_sha256` บน production ทั้ง 5 ไฟล์
2. **ใช้หน้าเอกสารจริงเป็นหลักฐานหลัก:** render หน้าที่เป็นหลักฐาน (และหน้าถัดไปเพื่อดูว่ารายการจบหรือไม่) เป็นภาพ แล้วเทียบข้อความทีละข้อกับค่าที่สกัด
3. **เทียบข้อความรายหน้าที่ระบบเก็บ** (`mko.document_pages.text_clean`) — ทุกข้อพบครบ
4. **text layer ของ PDF** (PyMuPDF) ใช้เป็นหลักฐานรองเท่านั้น จุดที่ไม่ตรงเกิดจากการเข้ารหัสอักขระในไฟล์ ไม่ใช่เนื้อหาต่าง:
   - `it66.pdf` เก็บวรรณยุกต์เป็น private-use glyph (U+F70E, U+F70B)
   - `ma69.pdf` / `cs66_brief.pdf` เก็บ "ำ" ต่างรูป
5. **ไม่ได้ใช้คำตอบ RAG** และไม่ได้ใช้ข้อมูลของหลักสูตรฉบับปีอื่นมายืนยัน
6. **เลขหน้า** ในรายงานนี้คือลำดับหน้าใน PDF (ตรงกับ `mko.evidence`) ซึ่งอาจต่างจากเลขหน้าที่พิมพ์ท้ายกระดาษ

**ข้อสังเกตที่ใช้กับทุกรายการ:** ข้อความที่สกัดมีช่องว่างเกินตรงจุดที่ PDF ตัดบรรทัด
- เมื่อไม่นับช่องว่าง ข้อความตรงต้นฉบับทุกตัวอักษร
- ระบบ review ทำได้เพียง verified / rejected ค่าที่สกัดมาตามที่เป็น แก้ข้อความเองไม่ได้
- ช่องว่างลักษณะเดียวกันมีอยู่แล้วใน objectives ที่ live ด้วยกฎอัตโนมัติ

## ถ้าได้รับอนุมัติให้บันทึก (ยังไม่ได้ทำ)

1. **ผลต่อฐานข้อมูล:**
   - `mko.review_decisions` เพิ่ม 6 แถว (verified 5, rejected 1) ด้วยชื่อผู้ตรวจที่ผู้อนุมัติระบุ
   - `reapply` เปลี่ยนสถานะ `field_values` และ `list_items` ของ 6 หน่วยนี้เป็น verified / rejected (`reviewed_by = human:<ชื่อ>`)
2. **ผลต่อ shadow และผู้ใช้:** ไม่มีจนกว่าจะ publish ครั้งใหม่ ซึ่งยังไม่ได้รับอนุมัติ — backend อ่านเฉพาะ `mko.v_live_*` ของ publication ปัจจุบัน
3. **ผลที่คาดเมื่อ publish ในอนาคต** (ถ้าอนุมัติแยก):
   - careers ของ IT 2566, คณิตศาสตร์ 2564, CS 2566
   - total_credits ของคณิตศาสตร์ 2569
   - objectives ของ CS 2566 จาก `cs66.pdf`
   - ทั้งหมดจะเข้า live
   - ด้วยนโยบายปัจจุบัน `verified_any` publication ใหม่จะรวมค่า auto ที่ live อยู่เดิมด้วย
   - ถ้าใช้ `verified_human_only` จะมีเฉพาะ 5 หน่วยนี้ ค่า auto 46 ค่าที่ live อยู่จะหายไป — การเลือกนโยบายไม่อยู่ในขอบเขตรอบนี้

## สิ่งที่ไม่ได้ทำ

- ไม่ได้เขียน `review_decisions`
- ไม่ได้เปลี่ยนสถานะข้อมูล
- ไม่ได้ publish / deploy / commit / push
- ไม่ได้ review P2/P3/P4 หรือ field อื่น
- ไม่ได้แก้ extraction rules
- ไม่ได้เปลี่ยน publish policy
- ไม่ได้เปิด `STRUCTURED_ANSWERS=on` หรือเริ่ม Phase 3
- คำสั่งกับ production เป็นแบบ read-only (`BEGIN READ ONLY … ROLLBACK`)
- ภาพหน้าเอกสารและสคริปต์ตรวจอยู่ใน scratchpad ของเครื่อง ไม่ได้อยู่ใน repo
