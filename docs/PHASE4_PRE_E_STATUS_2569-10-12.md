## 1. แก้วิธีทดสอบ login — เสร็จ

สคริปต์เดิมที่ผมเสนอไว้มีปัญหาสี่จุด แก้ครบแล้วที่ `/home/ubuntu/phase4-test-login.sh`

| ปัญหาเดิม | แก้เป็น |
|---|---|
| `printf '{"email":"%s","password":"%s"}'` — **รหัสผ่านที่มี `"` หรือ `\` ทำให้ JSON พังทันที** | ประกอบด้วย `python3 json.dumps` ผ่าน environment variable |
| พิมพ์คำตอบทั้งก้อนด้วย `head -c 120` ซึ่ง**เผย `access_token`** | รายงานแค่ `access_token = มี/ไม่มี` · **ไม่พิมพ์ค่า token เลย** |
| ใช้ `/tmp/login.json` ชื่อคงที่ — ผู้ใช้อื่นบนเครื่องสร้างไฟล์ดักไว้ก่อนได้ | `mktemp -d` ในโฟลเดอร์ส่วนตัว โหมด 700 |
| ลบไฟล์ด้วย `rm` ท้ายคำสั่ง — ถ้ากด Ctrl-C ไฟล์ค้าง | `umask 077` · ไฟล์โหมด 600 · `trap cleanup EXIT INT TERM` |

ทดสอบการประกอบ JSON กับรหัสผ่านที่มีอักขระยาก

```
รหัสผ่านทดสอบ: ab"c\d'e ฟ้า#1
ผลลัพธ์: {"email": "a\"b@x.ac.th", "password": "ab\"c\\d'e ฟ้า#1"}
```

JSON ถูกต้องทั้งเครื่องหมายคำพูด แบ็กสแลช อัญประกาศเดี่ยว `#` และภาษาไทย

## 2. เทอร์มินัลทดสอบ auth — พร้อมแล้ว

สคริปต์จะรายงานสามช่วง โดย **ไม่แสดง token และไม่บันทึกรหัสผ่านลงที่ใด**

1. สถานะบัญชี **ก่อน** เข้าสู่ระบบ — `role` · `status` · `password_scheme` · จำนวนเซสชัน
2. ผลการยิง `POST /api/auth/login` — HTTP code และมี token หรือไม่
3. สถานะบัญชี **หลัง** เข้าสู่ระบบ — ค่าเดิมทั้งหมด + `last_login_at` + `failed_login_count`

### ต้องทดสอบสองบัญชี

| บัญชี | คาดว่าจะได้ |
|---|---|
| **admin เดิม** (`te*****@gmail.com`) | `scheme` เป็น `bcrypt_sha256` อยู่แล้ว · เข้าได้ด้วยรหัสเดิม · `role=admin` |
| **บัญชีที่นำเข้า** (`66*****@365.pnru.ac.th` หรือ `66*****@pnru.ac.th`) | `scheme` เริ่มที่ **`bcrypt`** → เข้าสำเร็จแล้วต้อง **เปลี่ยนเป็น `bcrypt_sha256` เอง** |

**ข้อที่สองคือหลักฐานว่าการย้ายรหัสผ่านจาก Supabase ใช้ได้จริง** — ถ้าเข้าได้ แปลว่าไม่มีใครต้องตั้งรหัสใหม่
