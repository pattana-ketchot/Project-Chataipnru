## 1. ฟอนต์ที่เบราว์เซอร์ใช้จริง (ตรวจก่อนแก้ ไม่ได้อ่านจากชื่อใน CSS)

อ่านจาก `document.fonts` และ `getComputedStyle` บนหน้าที่รันจริง

```
ประกาศไว้ที่  src/index.css  * { font-family: 'Prompt', sans-serif }
ไฟล์ฟอนต์     Google Fonts — Prompt:wght@300;400;500;600;700  (<link> ใน index.html)
subset        ไทย U+0E01–0E5B และ ละติน U+0000–00FF แยกไฟล์กัน แต่เป็นตระกูลเดียวกัน
fallback      sans-serif — ไม่ได้ถูกใช้ เพราะ Prompt โหลดครบ
```

| จุด | ก่อนแก้ (จอ 1440) | หลังแก้ |
|---|---|---|
| หัวข้อ | Prompt **700** · 60px · line-height **60px (1.0)** | Prompt **600** · 52px · 64.5px (1.24) |
| ป้ายบรรทัดบน (ละติน) | Prompt 500 · 20px | Prompt 500 · 18px + `tracking-wide` |
| ข้อความรอง | Prompt 400 · 20px | Prompt 400 · 18px (มือถือ 14px → **15px**) |
| ปุ่ม | Prompt 600 · 18px | เท่าเดิม |

ยืนยันว่าน้ำหนัก 600 มีจริงทั้งสอง subset: `document.fonts.check('600 52px Prompt', …)` คืน `true`
ทั้งข้อความไทยและ `PNRU` และหลังแก้มีหน้าฟอนต์ `600 thai` + `600 latin` อยู่ในรายการที่โหลดแล้ว
— หัวข้อ ข้อความรอง และปุ่ม จึงเป็น Prompt ตระกูลเดียวกันทั้งหมด **ไม่ได้เพิ่มฟอนต์ใหม่**

## 2. ทำไมต้องคุม line-height ใน CSS ไม่ใช่ `leading-tight`

เดิมหัวข้อเขียน `leading-tight` (1.25) ไว้ แต่ค่าที่ออกมาจริงคือ **1.0** เพราะ `lg:text-6xl`
อยู่ใน media query จึงชนะ `leading-*` ที่ไม่มี breakpoint — `leading-tight` ไม่เคยมีผล
จึงย้ายไปคุมที่ `.hero-section .hero-heading h1` จุดเดียว (เฉพาะ Hero) ให้ชนะแน่นอนทุกขนาดจอ

## 3. แผ่นรองหลังข้อความ — ของเดิมมองไม่เห็นมาตลอด

ชั้น `bg-cream/80 backdrop-blur-lg` ที่ตั้งใจให้ข้อความอ่านง่ายนั้นเป็น `-z-10`
ซึ่งดันมันไปอยู่**หลังรูป Hero** (รูปเป็น `absolute` z auto) ทดสอบโดยบังคับให้เป็นสีแดงทึบ
แล้วถ่ายภาพ — ไม่เห็นสีแดงเลย ยืนยันว่าชั้นนี้ไม่เคยทำงาน ข้อความจึงวางบนภาพตรง ๆ

แก้โดยเอา `-z-10` ออก และให้กล่องข้อความเป็น `relative` (ข้อความทับแผ่นตามลำดับใน DOM)
แล้วลดความทึบลงเป็น `bg-cream/75 backdrop-blur-md` ขอบยังเป็นเงาจาง ๆ เหมือนเดิม
**ภาพ ขนาดบล็อก ตำแหน่งปุ่ม และโครงหน้าไม่เปลี่ยน**

## 4. บรรทัดไทยที่ถูกตัดแปลก ๆ บนมือถือ

`<br />` ตายตัวทำให้จอ 375px ได้ผลลัพธ์เป็น

```
ตอบแบบสอบถามสั้น ๆ เพื่อค้นหาสาขาที่เหมาะกับ
ความถนัด                 ← ห้อยเดี่ยว
และความสนใจของคุณ
```

เปลี่ยนเป็น `<br className="hidden md:inline" />` — จอเล็กขึ้นบรรทัดเองตามความกว้าง
ได้สองบรรทัดเต็ม ส่วนจอ md ขึ้นไปยังขึ้นบรรทัดตรงจุดเดิมทุกประการ (ตรวจแล้วที่ 768px `display: inline`)

## 5. ผลตรวจหน้าจอ

| จอ | ผล |
|---|---|
| 1920 × 1000 | หัวข้อสองบรรทัดพอดี ไม่ล้น ปุ่มรูปเดิม |
| 1440 × 900 | หัวข้อ 52px/600 กว้าง 592px = ความกว้างกล่อง ไม่ล้น · `scrollWidth == clientWidth` |
| 768 × 900 (md) | `<br>` กลับมาทำงาน ข้อความรองสองบรรทัด ปุ่ม 161×46 |
| 375 × 812 (mobile) | ข้อความรองสองบรรทัดไม่มีคำห้อย · ปุ่ม 142×44 · ไม่มีการเลื่อนแนวนอน |

**สระและวรรณยุกต์ไม่ถูกตัด** — วัดด้วย `measureText` ที่ 600 52px Prompt
หมึกสูงสุดของบรรทัด "ค้นหาสาขาที่ใช่" อยู่ที่ 52px เหนือเส้นฐาน และหัวสระของบรรทัดล่าง
เริ่มต่ำกว่าหมึกล่างสุดของบรรทัดบน **26px** จึงไม่ชนกัน และ `.hero-section` เป็น `overflow-visible`
อยู่แล้วจึงไม่มีการตัดขอบ · ทุกจอ `documentElement.scrollWidth - clientWidth = 0`

ภาพก่อน–หลังจากหน้าที่รันจริง (`npm run dev`)
