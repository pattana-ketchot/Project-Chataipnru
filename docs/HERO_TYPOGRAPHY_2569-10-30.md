## 1. ฟอนต์ที่เบราว์เซอร์ใช้จริง (ตรวจก่อนแก้ ไม่ได้อ่านจากชื่อใน CSS)

อ่านจาก `document.fonts` และ `getComputedStyle` บนหน้าที่รันจริง

```
ประกาศไว้ที่  src/index.css  * { font-family: 'Prompt', sans-serif }
ไฟล์ฟอนต์     Google Fonts — Prompt:wght@300;400;500;600;700  (<link> ใน index.html)
subset        ไทย U+0E01–0E5B และ ละติน U+0000–00FF แยกไฟล์กัน แต่เป็นตระกูลเดียวกัน
fallback      sans-serif — ไม่ได้ถูกใช้ เพราะ Prompt โหลดครบ
```

ยืนยันว่าน้ำหนัก 600 มีจริงทั้งสอง subset (`document.fonts.check` คืน `true` ทั้งข้อความไทยและ `PNRU`)
หัวข้อ ข้อความรอง และปุ่ม เป็น Prompt ตระกูลเดียวกันทั้งหมด **ไม่ได้เพิ่มฟอนต์ใหม่เข้าโปรเจกต์**

| จุด | ก่อน (จอ 1440) | หลัง |
|---|---|---|
| หัวข้อ | 700 · 60px · line-height **1.0** | **600** · 52px · **1.24** |
| ชื่อมหาวิทยาลัย | 500 · 20px ตัวพิมพ์ปกติ | **600 · 14px ตัวพิมพ์ใหญ่ เว้นระยะ 0.18em + ขีดสีเขียวเหนือบรรทัด** |
| ข้อความรอง | 400 · 20px (มือถือ 14px) | 400 · 18px (มือถือ **16px**) |
| ปุ่ม | 600 · 18px พื้นไล่เฉด | 600 · 18px **พื้นสีเดียว `#016a2b`** |

## 2. ทำไมต้องคุม line-height ใน CSS ไม่ใช่ `leading-tight`

หัวข้อเขียน `leading-tight` (1.25) ไว้ แต่ค่าจริงคือ **1.0** เพราะ `lg:text-6xl` อยู่ใน media query
จึงชนะ `leading-*` ที่ไม่มี breakpoint — `leading-tight` ไม่เคยมีผล จึงย้ายไปคุมที่
`.hero-section .hero-heading h1` จุดเดียว ให้ชนะแน่นอนทุกขนาดจอ

## 3. ให้ตัวอักษรเข้ากับพื้นหลัง — เปลี่ยนจากแผ่นลอยเป็นม่านสีไล่ระดับ

เดิมมีแผ่น `bg-cream/80 backdrop-blur-lg` สี่เหลี่ยมมนอยู่หลังข้อความ แต่ตั้งเป็น `-z-10`
ซึ่งดันมันไป**อยู่หลังรูป Hero** (รูปเป็น `absolute` z auto) ทดสอบโดยบังคับให้เป็นสีแดงทึบ
แล้วถ่ายภาพ — ไม่เห็นสีแดงเลย ยืนยันว่าชั้นนี้ไม่เคยทำงาน ข้อความวางบนภาพตรง ๆ มาตลอด

รอบนี้ถอดแผ่นนั้นออกทั้งก้อน แล้วใช้**ม่านสีครีมไล่ระดับคลุมทั้งแถบ Hero** แทน
เพราะแผ่นสี่เหลี่ยมมนเห็นขอบชัดเป็นกล่องลอยทับรูป ส่วนม่านไล่ระดับจะค่อย ๆ จางเข้าหาภาพ
ตัวอักษรจึงดูอยู่บนพื้นเดียวกับรูป ไม่ใช่วางซ้อนอยู่คนละชั้น

```
จอกว้าง (xl ขึ้นไป)  ไล่ซ้าย→ขวา   ทึบ 0.96 → จาง 0 ที่ 78% ของความกว้าง
จอแคบกว่านั้น        ไล่บน→ล่าง    ทึบ 0.96 → จาง 0 ที่ 88% ของความสูง
```

เลือกจุดจางตามตำแหน่งข้อความจริงของแต่ละช่วงจอ (จอกว้างข้อความอยู่ครึ่งซ้าย
จอแคบข้อความอยู่ครึ่งบน) ม่านจึงยังทึบอยู่จนพ้นขอบข้อความทุกบรรทัด
**ภาพ ขนาดบล็อก ตำแหน่งปุ่ม และโครงหน้าไม่เปลี่ยน** — คนในภาพยังเห็นชัดเหมือนเดิม

### ค่าความต่างสีที่วัดได้จริง

วัดโดยอ่านพิกเซลของรูป Hero ที่ตำแหน่งใต้ข้อความแต่ละก้อน (คำนวณตาม `object-fit: cover`
และ `object-position: 50% 80%` ที่ใช้จริง) ผสมกับม่านสีตามสูตรข้างบน แล้วคิดอัตราส่วน
ความต่างสีแบบ WCAG เทียบกับสีตัวอักษร — ตัวเลขคือ**ค่าต่ำสุด**ที่เจอในกรอบข้อความ

| ข้อความ | ก่อน (1440) | หลัง (1440) | หลัง (มือถือ 375) | เกณฑ์ |
|---|---|---|---|---|
| ชื่อมหาวิทยาลัย | **4.09** | 7.65 | 7.71 | ≥ 4.5 |
| หัวข้อบรรทัดเขียว | **3.66** | 5.42 | 5.80 | ≥ 4.5 |
| หัวข้อบรรทัดดำ | 12.08 | 16.93 | 17.65 | ≥ 4.5 |
| ข้อความรอง | 5.69 | 11.56 | 10.20 | ≥ 4.5 |

ก่อนแก้มีสองก้อนที่ต่ำกว่า 4.5 คือชื่อมหาวิทยาลัยและหัวข้อบรรทัดสีเขียว (ตรงจุดที่ไปทับส่วนสว่างของภาพ)
หลังแก้ผ่านเกณฑ์ทั้งหมดทั้งบนเดสก์ท็อปและมือถือ

## 4. ให้ดูเป็นทางการขึ้น

* **ชื่อมหาวิทยาลัยกลายเป็นป้ายกำกับ** — ตัวพิมพ์ใหญ่ เว้นระยะตัวอักษร ขนาดเล็กลง
  และมีขีดสั้นสีเขียวของมหาวิทยาลัยอยู่เหนือบรรทัด แบบหัวกระดาษเอกสารราชการ
  (ทำด้วย `::before` ใน CSS จึงไม่ต้องเพิ่ม element และเคลื่อนไหวเข้าพร้อมบรรทัดเดิม)
* **หัวข้อลดน้ำหนักจากหนา (700) เป็นกึ่งหนา (600)** และลดขนาดลงหนึ่งระดับ ไม่ตะโกน
* **ปุ่มเปลี่ยนจากพื้นไล่เฉดมันวาวเป็นสีเขียวเรียบสีเดียวของมหาวิทยาลัย** (`#016a2b`)
  ทรงและขนาดปุ่มเท่าเดิมทุกประการ
* **ไม่เปลี่ยนข้อความ ไม่เปลี่ยนสีประจำตัวของหัวข้อ และไม่เพิ่มฟอนต์ใหม่**

## 5. ผลตรวจหน้าจอ

| จอ | ม่านที่ใช้ | ผล |
|---|---|---|
| 1920 × 1000 | ซ้าย→ขวา | ข้อความอยู่บนพื้นเรียบ คนในภาพยังชัด ไม่ล้น |
| 1440 × 900 | ซ้าย→ขวา | หัวข้อ 52px/600 กว้าง 592px พอดีกล่อง `scrollWidth == clientWidth` |
| 1100 × 820 | บน→ล่าง | หัวข้อและข้อความรองอ่านชัด ภาพครึ่งล่างยังคมเหมือนเดิม |
| 768 × 900 | บน→ล่าง | `<br>` ทำงานตามเดิม ข้อความรองสองบรรทัด ปุ่ม 161×46 |
| 375 × 812 | บน→ล่าง | ข้อความรองสองบรรทัดไม่มีคำห้อย ปุ่ม 142×44 ไม่มีการเลื่อนแนวนอน |

**สระและวรรณยุกต์ไม่ถูกตัด** — วัดด้วย `measureText` ที่ 600 52px Prompt หมึกสูงสุดของบรรทัดบน
อยู่ 52px เหนือเส้นฐาน และหัวสระของบรรทัดล่างเริ่มต่ำกว่าหมึกล่างสุดของบรรทัดบน **26px**
จึงไม่ชนกัน · `.hero-section` เป็น `overflow-visible` อยู่แล้วจึงไม่มีการตัดขอบ
· ทุกจอ `documentElement.scrollWidth - clientWidth = 0`

ภาพก่อน–หลังจากหน้าที่รันจริง (`npm run dev`)

## 6. ที่ยังไม่ได้ทำ

* ยังใช้ฟอนต์ Prompt เดิมตามที่สั่งว่าให้เลือกจากฟอนต์ที่โปรเจกต์มีอยู่ก่อน
  ถ้าต้องการความรู้สึก "เอกสารราชการ" มากกว่านี้ ต้องเพิ่มฟอนต์อย่าง Sarabun เข้ามา
  ซึ่งเป็นการเพิ่มไฟล์ฟอนต์ที่โหลดทุกหน้า — ยังไม่ได้ทำ รอสั่ง
* หัวข้อ Hero ยังเป็น `<h1>` สองอันในหน้าเดียว ซึ่งผิดโครงสร้างหัวเรื่องของหน้า
  แต่เป็นคนละเรื่องกับตัวอักษร จึงไม่แตะในรอบนี้
* ส่วนอื่นของหน้าแรกยังใช้ขนาด น้ำหนัก และสีเดิมทั้งหมด
