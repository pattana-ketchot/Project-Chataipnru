### 3.1 ปัญหาที่เจอระหว่างทาง และการแก้

สาเหตุ: บรรทัดตรวจว่ามีฐานข้อมูลอยู่จริงใช้ `docker exec -i` ซึ่ง `-i` ผูก stdin

ตรวจแล้วว่า production ไม่ถูกแตะเลย (ยัง 12 แถว ไม่มีโฟลเดอร์ run ใหม่)
แก้โดยตัด `-i` ออกจากบรรทัดนั้น (คำสั่งนั้นไม่ต้องใช้ stdin อยู่แล้ว)
และตรวจ `rollback_data.sh` ว่าไม่มีปัญหาเดียวกัน — บรรทัด `docker exec -i` ในไฟล์นั้น

### 5.2 ข้อที่ผ่านบางส่วน — บทสนทนาถามระดับต่อเนื่อง

**ส่วนที่ทำงานถูกต้อง**

เทิร์นที่ 1 บนหน้าแชตจริง — ถาม "การจัดการเทคโนโลยีการเกษตรและบริหารทรัพยากรชุมชน เรียนกี่หน่วยกิต"

> หลักสูตรการจัดการเทคโนโลยีการเกษตรและบริหารทรัพยากรชุมชน มีทั้งระดับปริญญาโท และ ปริญญาเอก ช่วยระบุระดับที่ต้องการด้วยครับ จะได้ตอบจากเล่มที่ถูกระดับ

เทิร์นที่ 2 — ตอบ "ปริญญาโท" → ระบบ**ต่อบริบทได้ ไม่ถามซ้ำ และอ้างเล่มถูกระดับ**
(ขึ้นชื่อ "หลักสูตรวิทยาศาสตรมหาบัณฑิต") **ไม่มีการหยิบเล่มปริญญาเอกมาตอบ**

**ส่วนที่ยังไม่ดี**

คำตอบของเทิร์นที่ 2 คือ *"ไม่พบข้อมูลจำนวนหน่วยกิตทั้งหมดของหลักสูตรวิทยาศาสตรมหาบัณฑิต…"*
พร้อมหมายเหตุว่ายังยืนยันกับเอกสารไม่ได้ — คือตอบถูกเล่มแต่หาคำตอบไม่เจอ

**วัดซ้ำแล้ว ไม่ใช่ความผันผวนของโมเดล** — ยิงซ้ำ 3 ครั้ง ได้ผลเดิม 2 ครั้ง
อีก 1 ครั้งโมเดลล่มชั่วคราว ("ระบบตอบไม่ได้ในขณะนี้")

**หาสาเหตุได้แล้ว** — ไม่ได้อยู่ที่ด่านถามระดับ แต่อยู่ที่การเขียนคำถามต่อเนื่องใหม่

| สิ่งที่ถาม | ผลบน production |
|---|---|
| ข้อความเดียว "ปริญญาโท…เรียนกี่หน่วยกิต" | **ไม่น้อยกว่า 36 หน่วยกิต** ถูกต้อง |
| ข้อความเดียว "ปริญญาเอก…เรียนกี่หน่วยกิต" | **ไม่น้อยกว่า 48 หน่วยกิต** ถูกต้อง |
| ตอบต่อเนื่องว่า "ปริญญาโท **เรียนกี่หน่วยกิต**" | **ถูกต้อง** |
| ตอบต่อเนื่องว่า "ปริญญาโท" เฉย ๆ | **ไม่พบข้อมูล** |

เมื่อผู้ใช้ตอบแค่ระดับ ระบบเขียนคำถามใหม่เป็น
*"หลักสูตรการจัดการเทคโนโลยีการเกษตรและบริหารทรัพยากรชุมชน ระดับปริญญาโท"*
ซึ่ง**ไม่มีคำว่า "เรียนกี่หน่วยกิต" ติดมาด้วย** เส้นทางตอบจากฐานข้อมูลจึงไม่ทำงาน
และการค้นเอกสารก็ค้นด้วยคำที่ไม่มีคำว่าหน่วยกิต จึงดึงหน้าที่ไม่เกี่ยวมา

เป็นข้อจำกัดของการต่อบริบท **ไม่ใช่ของด่านถามระดับที่เพิ่งขึ้น** — ด่านทำงานตามที่ออกแบบ
ทุกประการ (ถามกลับ · ไม่เดาระดับ · เลือกเล่มถูกเมื่อผู้ใช้ตอบ)

พร้อมหมายเหตุให้ไปตรวจเอกสาร ซึ่งเป็นพฤติกรรมที่ระบบตั้งใจทำเมื่อไม่มั่นใจ

**การตัดสินใจขั้นสุดท้ายเป็นของอาจารย์** ถ้าสั่งย้อน ทำได้ทันทีด้วย

```bash
cd /home/ubuntu/grad-programs-2569-10-27
./rollback_web.sh  --run web-run-20261027-155137
./rollback_data.sh --db course_advisor --run run-20261027-155118
./rollback_backend.sh
```

ทั้งสามสคริปต์ทดสอบเต็มวงจรมาแล้วบนฐานทดสอบ และ `rollback_data.sh` ถอนเฉพาะคีย์ที่
release นี้เพิ่ม จึงไม่ลบงานที่ผู้ดูแลแก้เพิ่มหลัง deploy

**ข้อเสนอ** — เก็บสภาพปัจจุบันไว้ แล้วแก้การต่อบริบทให้ยกหัวข้อคำถามเดิมมาด้วย
เป็นงานรอบถัดไป (ไม่ได้ทำในรอบนี้ตามที่สั่งว่าไม่รวมงานอื่นเพิ่ม)
