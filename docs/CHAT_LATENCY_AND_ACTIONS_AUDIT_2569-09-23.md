## 1.2 เจอสองเรื่อง ไม่ใช่เรื่องเดียว

### เรื่องที่ 1 — `streaming = 0.00` ทุกครั้ง คือต้นเหตุที่ `•••` ค้างนาน

**คำตอบไม่ได้ทยอยมาทีละตัวอักษร แต่มาทีเดียวทั้งก้อนตอนจบ**
`pre_stream` จึงเท่ากับ `total` เกือบทุกครั้ง แปลว่าผู้ใช้เห็นจุดสามจุดตลอดเวลาที่รอ
แล้วคำตอบก็โผล่มาพรวดเดียว

สาเหตุอยู่ที่ลำดับใน `services/chat.py:1466`

```python
p = _with_structured(prepare_answer(db, ...), message)   # <-- ทำงานหนักทั้งหมดตรงนี้
yield _sse("meta", {...})                                 # แล้วค่อยส่ง meta
if p.canned is not None:
    yield _sse("token", {"t": p.canned})                  # คำตอบทั้งก้อนใน token เดียว
```

`routes/web_compat.py` ดึงเหตุการณ์แรกด้วย `next(stream, "")` เพื่ออ่าน header
จึงถูกบล็อกจนกว่า `prepare_answer` จะเสร็จ **ซึ่งเป็นพฤติกรรมเดิม ไม่ได้เกิดจากของที่เพิ่งแก้**

ยิ่งกว่านั้น เส้นทาง structured/แคช ตั้ง `p.canned` เป็นคำตอบเต็ม แล้ว yield ครั้งเดียว
ต่อให้ไม่มี `next()` ก็ยังไม่มีอะไรให้ทยอยแสดงอยู่ดี

## 1.3 `_source_headers()` ที่เพิ่งเพิ่ม ทำให้ช้าลงไหม — **ไม่**

- query เป็นการค้นด้วย primary key แล้ว join หนึ่งชั้น วัดด้วย `EXPLAIN ANALYZE` ได้ **0.126 ms**
- คิดเป็น **0.006%** ของคำขอ 2.2 วินาที
- ทำงาน **หลัง** `prepare_answer` เสร็จแล้ว จึงไม่ได้เพิ่มงานก่อนเริ่มสตรีมอย่างมีนัย
- คำถามที่ไม่มี source จะ `return {}` ตั้งแต่ต้น **ไม่แตะฐานข้อมูลเลย**

# ส่วนที่ 2 — ทำไม AnswerActions ไม่ขึ้น

## 2.1 Header จริงของคำถามนั้น

```
POST /api/chat   "สนใจสาขาวิทยาการคอมพิวเตอร์ต้องทำไง"
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
X-Accel-Buffering: no
```

**ไม่มี `X-Source-*` สักตัว** — ไม่มี Document, Page, Title, Programme
ขณะที่คำตอบเขียนชัดว่า "หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาวิทยาการคอมพิวเตอร์"

## 2.2 หลังบ้านตอบจากเส้นทางไหน

**RAG เต็มรูปแบบ** (`status = "answered"`, `p.canned = None`) — ให้โมเดลเขียนคำตอบสดจาก chunk ที่ค้นได้
ยืนยันจาก `streaming = 2.4s` และมี `streamGenerateContent` ใน log
ไม่ใช่เส้นทาง structured ที่ดึงคำตอบจากตาราง `mko`

## 2.3 ข้อมูลสาขาที่ยืนยันได้ มีอยู่แล้วตรงไหน

**มีอยู่แล้ว และอยู่ใน meta event ที่ `chat_web` อ่านอยู่แล้วด้วย**

`schemas/chat.py:14` — ทุก citation มีข้อมูลนี้ครบ

```python
class ChatCitation(BaseModel):
    chunk_id: uuid.UUID
    course_id: uuid.UUID      # <-- FK ไป courses ของ PostgreSQL
    course_title: str         # <-- ชื่อหลักสูตรเต็ม
    page_number: int | None
    score: float
```

และ meta ที่ yield ออกมา (`chat.py:1474`) มี `"citations": [...]` อยู่แล้ว

`course_id` กับ `course_title` มาจาก **chunk ที่ระบบค้นเจอจริง** ซึ่งผูกกับ
`course_chunks.course_id` → `courses` เป็น FK ในฐานข้อมูล
**ไม่ใช่การอ่านข้อความที่โมเดลเขียน**

## 2.4 เหตุผลที่ปุ่มไม่ขึ้น

โซ่เหตุผลสั้น ๆ

1. `p.source` ถูกตั้งค่า**ที่เดียวเท่านั้น** คือ `chat.py:1025` ในเส้นทาง structured
   (`served_source=SERVED_STRUCTURED`)
2. เส้นทาง RAG ไม่เคยตั้ง `p.source` → เป็น `None`
3. `_source_headers()` เริ่มด้วย `if not document_id: return {}` → **ไม่ส่ง header อะไรเลย**
4. หน้าเว็บจึงได้ `documentId = ""` และ `programme = ""`
5. `AnswerActions.jsx` มี `if (!documentId && !programme) return null` → **ไม่ render ทั้งกล่อง**

**สรุป: ผมผูกบริบทสาขาไว้กับการมีเอกสาร PDF ซึ่งเป็นการออกแบบที่ผิด**
สองอย่างนี้เป็นคนละเรื่องกัน ตรงตามที่ทักมา

## 2.5 วิธีแก้ที่ไม่ต้องเดาจากข้อความ AI

### หลังบ้าน — ส่งบริบทสาขาแยกจากเอกสาร

เพิ่ม header ใหม่ที่คำนวณจาก `p.citations` ไม่ใช่จาก `p.source`

```
X-Course-Programme : ชื่อหลักสูตรจาก citation ที่คะแนนสูงสุด (base64 UTF-8)
```

- เลือกจาก citation ที่ score สูงสุด หรือหลักสูตรที่ปรากฏบ่อยที่สุดใน citations
- ส่งเฉพาะเมื่อ `status == "answered"` และมี citation จริง
- ไม่มี citation ก็ไม่ส่ง

### ⚠️ ข้อควรระวังเรื่อง `X-Course-Id` ที่เสนอมา

**ผมไม่แนะนำให้ส่ง `X-Course-Id`** เพราะ `citations[].course_id` เป็น id ของ
**PostgreSQL** ซึ่ง**คนละชุดกับ id ของ Supabase** ที่หน้าเว็บใช้เปิดหน้า `/courses/{id}`
ถ้าส่งไปตรง ๆ หน้าเว็บจะเปิดหน้าไม่เจอ

ควรส่ง **ชื่อหลักสูตร** แล้วให้ `programmeLinks.js` แปลงเป็น Supabase courseId
ซึ่งเป็นกลไกเดิมที่ตรวจแล้วว่าใช้ได้จริงกับทั้ง 12 สาขา

### หน้าเว็บ — แยกเงื่อนไขของแต่ละปุ่มออกจากกัน

```
sourceDocument != null           -> 📄 ดูเอกสารหลักสูตร
programme resolve ได้            -> 🎓 ดูรายละเอียดสาขา + 🌐 เว็บไซต์สาขา PNRU
programme resolve ได้ (บริบทคณะ) -> 🏫 เว็บไซต์คณะ
```

โดย `programme` มาจาก `X-Source-Programme` (เส้นทาง structured) **หรือ**
`X-Course-Programme` (เส้นทาง RAG) อันไหนมาก่อนก็ใช้อันนั้น

ผลที่คาดกับคำถามนี้: ได้ 🎓 + 🌐 + 🏫 และถ้ามีเอกสารจริงด้วยจึงเพิ่ม 📄
