## 1. ยืนยันงานที่ค้างจากเมื่อวาน (ทำก่อนอย่างอื่น)

เมื่อวานแก้กติกาการแนะนำสาขาไปหลายข้อตามที่กำหนด แต่ **ยังไม่มีใครยืนยันว่าทำงาน
ถูกต้องจริง** เพราะโควตาหมดกลางการทดสอบ

### 1.1 เช็คว่าโควตากลับมาหรือยัง

ยิงคำถามเดียวไปที่ `/api/chat` ถ้าตอบว่า *"ระบบหลักตอบไม่ได้ชั่วคราว"* แปลว่ายังไม่รีเซ็ต

> โควตาชั้นฟรีของ Gemini คือ **500 คำขอต่อวันต่อโมเดล** หนึ่งคำถามของผู้ใช้ใช้ 3-4 คำขอ
> ชุดประเมิน 118 ข้อกินราว 400 คำขอ จึง **รันได้วันละรอบเดียว** และห้ามยิงคำถามอื่น
> แทรกระหว่างรัน เพราะจะไปเบียดโควตาแล้วผลกลายเป็น error

### 1.2 รันชุดตรวจพฤติกรรม

```bash
python eval/behaviour_check.py
```

เมื่อวานได้ **ผ่าน 6 / ตรวจไม่ได้ 4** เพราะโควตาหมด — ต้องได้ครบ 10 ข้อ

ข้อที่สำคัญที่สุดคือ **"แนะนำสาขาตามแก่นของหลักสูตร"** ซึ่งรันสองรอบได้ผลไม่ตรงกัน
เพราะตอนนั้นใช้โมเดลสำรองที่แกว่ง ต้องพิสูจน์ว่า

> ถาม "สาขาไหนเหมาะกับคนชอบทำงานกับคอมพิวเตอร์"
> ได้ **วิทยาการคอมพิวเตอร์ + เทคโนโลยีสารสนเทศ** และ **ห้ามมีการประกอบอาหาร**

### 1.3 รันชุดประเมิน 118 ข้อ

ค่าอ้างอิงล่าสุด **114/118 ไม่มีคำตอบที่แต่งข้อมูลจริง**

> **ห้ามอ่านผลต่างเล็กน้อยว่าดีขึ้นหรือแย่ลง** — รันชุดเดิมบนระบบที่ไม่ได้แก้อะไรเลย
> สองรอบ ได้ 112/113 กับ 109/113 คะแนนแกว่งราว 3 ข้อเป็นเรื่องปกติ ให้ตัดสินจาก
> **ชนิดของความผิดพลาด** เช่นมีคำตอบที่แต่งข้อมูลหรือไม่ ไม่ใช่จากตัวเลขรวม

## 2. เรื่องที่ยังไม่ได้ตัดสินใจ

### 2.1 เมื่อไม่ระบุปี ควรใช้ฉบับล่าสุดหรือไม่

ตอนนี้ระบบหยิบฉบับที่คะแนนความใกล้เคียงสูงกว่า ซึ่งบางครั้งได้ฉบับเก่า

| | ฉบับ 2561 | ฉบับ 2566 (ปัจจุบัน) |
|---|---|---|
| อาชีพของวิทยาการคอมพิวเตอร์ | 8 อาชีพ | 9 อาชีพ |
| มีนักวิทยาศาสตร์ข้อมูลไหม | ไม่มี | **มี** |

ถามว่าจบไปทำอาชีพอะไรได้ แล้วได้คำตอบจากฉบับ 2561 — ระบบบอกปีกำกับไว้จึงไม่ได้ปิดบัง
แต่คนถามส่วนใหญ่คือนักเรียนที่จะเข้าเรียนปีหน้า ซึ่งจะเรียนฉบับล่าสุด

**ข้อเสนอ** ถ้าไม่ระบุปี ให้ใช้ฉบับล่าสุดเสมอ (คนที่อยากได้ฉบับเก่ายังพิมพ์ปีระบุได้)
แก้ที่ `_narrow_by_year()` ใน `backend/app/services/course_scope.py`

**ยังไม่ได้ทำ** ต้องรันชุดประเมินพิสูจน์ว่าคำถามที่ระบุปีเจาะจงยังตอบถูกเหมือนเดิม

### 2.2 รวมคำขอสองขั้นเป็นขั้นเดียว

ตอนนี้หนึ่งคำถามใช้ 3-4 คำขอ — ย่อบทสนทนา, ตรวจขอบเขต, ตรวจว่าเอกสารตอบได้, เขียนคำตอบ
การรวมสองขั้นกลางเข้าด้วยกันจะเหลือ 2-3 คำขอ **ประหยัดโควตาราว 30%**

**ยังไม่ได้ทำ** เพราะไปแตะด่านที่ตัดสินว่าจะตอบหรือไม่ตอบ ซึ่งเป็นหัวใจของการไม่มั่ว
ต้องรันชุดประเมินพิสูจน์ว่าไม่หลวมลง

## 4. กติกาที่ต้องรักษาไว้

**ห้ามอัปโหลดไฟล์ที่มี API key ขึ้น GitHub เด็ดขาด**

**แก้ตรรกะการตอบเมื่อไหร่ ต้องเพิ่ม `_LOGIC_VERSION`** ใน
`backend/app/services/answer_cache.py` ด้วยเสมอ

> ระบบเก็บคำตอบไว้ใช้ซ้ำโดยผูกกับสภาพคลังเอกสาร + ค่า k + เลขรุ่นของตรรกะ
> ถ้าลืมเพิ่มเลขรุ่น จะทดสอบแล้วได้คำตอบเก่าจากแคชแบบเดิมทุกตัวอักษร แล้วเข้าใจว่า
> แก้ไม่สำเร็จ ทั้งที่โค้ดถูกแล้ว — **เกิดขึ้นแล้ว 3 ครั้งในวันเดียว** และเกือบทำให้
> ไปรื้อโค้ดที่ถูกอยู่แล้ว

**ก่อนบอกว่าเสร็จ ให้รัน `eval/behaviour_check.py` ทุกครั้ง**

**อย่าเชื่อคำตอบเพราะอ่านแล้วดูเข้าท่า** — ความผิดพลาดที่แพงที่สุดในโปรเจกต์นี้ล้วนเป็น
คำตอบที่อ่านแล้วดูถูกต้องทุกประการ จับได้ก็ต่อเมื่อ query เอกสารต้นทางมานับเทียบ:

- อาชีพตอบมา 5 ข้อ เอกสารระบุ 8
- รายชื่อหลักสูตรแสดง 11 สาขา ควรเป็น 12 เพราะชื่อในไฟล์ต่างกันคำเดียว
- แนะนำหลักสูตรที่คณะเลิกเปิดสอนแล้ว 4 สาขา
- โมเดลสำรองตอบหน่วยกิต 180 ทั้งที่เอกสารเขียน 147

ทุกกรณีข้างบนผ่านชุดประเมินและผ่านสายตา
