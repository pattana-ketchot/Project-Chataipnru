## 1. สิ่งที่ผู้ใช้เห็น

ใต้เปอร์เซ็นต์ของการ์ดทุกใบ (ทั้งอันดับหลักและสาขาทางเลือก) มีปุ่ม
**"ทำไมได้คะแนนนี้?"** กดแล้วเปิดสี่ส่วน

1. **คำตอบของคุณที่ใช้คิดคะแนน** — เฉพาะข้อที่เข้าไปอยู่ในเวกเตอร์จริง พร้อมบรรทัดกำกับว่า
   ระบบใช้คำตอบชุดเดียวนี้เทียบกับทุกสาขา คะแนนที่ต่างกันจึงมาจากเนื้อหาของแต่ละสาขา
2. **ส่วนของเอกสารที่ใช้เทียบคะแนน** — ไฟล์ เลขหน้า ค่าความใกล้เคียงเชิงข้อความ และ
   **ข้อความต้นฉบับสั้น ๆ ของชิ้นนั้น** ปิดท้ายด้วยบรรทัดกำกับว่าความใกล้เคียงเชิงข้อความ
   เป็นค่าที่วัดจากเวกเตอร์ ไม่ใช่การยืนยันว่าเนื้อหาส่วนนี้ตรงกับคำตอบของผู้ใช้
3. **ส่วนที่ยังไม่พบข้อมูลเชื่อมโยง** — เขียนจากค่าที่วัดได้เท่านั้น: ไม่มีส่วนของเอกสารให้เทียบ,
   เอกสารมีเนื้อหาให้เทียบน้อยกว่า 5 ส่วน, ไม่พบข้อความที่ยืนยันเหตุผลได้, คำอธิบายใบนี้ไม่ได้
   มาจาก AI, และคำตอบข้อที่ระบบไม่ได้ใช้คิดคะแนน · ถ้าไม่มีข้อใดเลยจะเขียนว่า
   "ยังไม่มีรายละเอียดช่องว่างเพิ่มเติมจากข้อมูลที่ระบบตรวจในรอบนี้" **ไม่สรุปว่าตรงครบทุกข้อ**
4. **เปอร์เซ็นต์นี้คิดมาอย่างไร** — สูตรจริงพร้อมตัวเลขของใบนั้น ใช้ `≈` เพราะเลขที่แสดงถูกปัด
   สองตำแหน่งแล้ว มีบรรทัดบอกว่าระบบจำกัดคะแนนไว้ในช่วง 0–100 (ต่ำกว่า 0.35 เป็น 0%
   สูงกว่า 0.72 เป็น 100%) ปิดท้ายด้วยข้อความว่าเปอร์เซ็นต์คือระดับความสอดคล้องตามวิธี
   คำนวณของระบบ **ไม่ใช่โอกาสสอบติดและไม่ใช่การรับประกันว่าจะเรียนสำเร็จ**

> **ไม่มีเกณฑ์ผ่าน/ไม่ผ่านรายองค์ประกอบ** — ฉบับก่อนหน้านี้เคยเอาช่วง 0.35–0.72 ไปตัดสิน
> ความคล้ายของเนื้อหาและของชื่อสาขาทีละตัว ซึ่งเป็นเกณฑ์ที่ระบบไม่มี (ช่วงนั้นใช้กับ **คะแนน
> ผสม** ตอนแปลงเป็นเปอร์เซ็นต์เท่านั้น) · ตัดออกแล้ว ค่าทั้งสองแสดงตามจริงในส่วนที่ 4

เหนือรายการสาขา (กล่อง "สรุปจาก AI") มีสามบรรทัดตามที่ขอ

```
โมเดลเทียบความคล้าย: bge-m3 · โมเดลในเครื่อง
คะแนนคำนวณด้วยสูตรและเกณฑ์ของระบบ จากความใกล้เคียงระหว่างคำตอบของคุณกับเนื้อหาในเอกสารหลักสูตร
คำอธิบายโดย: Gemini · gemini-3.5-flash-lite
```

กรณีไม่ได้ใช้ข้อความจาก AI บรรทัดที่สามเปลี่ยนเป็น
`ไม่ได้ใช้ข้อความจาก AI ในผลชุดนี้ · ประมวลผลจากข้อมูลและเกณฑ์ของระบบ` — **ไม่มีชื่อรุ่นใด
ปรากฏบนหน้าจอเลย** (ตรวจแล้ว ดูข้อ 4)

> หมายเหตุการเปลี่ยนถ้อยคำ: บรรทัดผู้เขียนคำอธิบายเดิมคือ `คำอธิบายโดย Gemini · …`
> ตอนนี้มีทวิภาคเป็น `คำอธิบายโดย: Gemini · …` ตามรูปแบบที่สั่งไว้ · ใครค้นสตริงนี้ในชุด
> ตรวจหรือใน bundle ต้องเปลี่ยนคำค้นตาม

## 2. หลังบ้านส่งอะไรมา (ของจริงจากการคำนวณ ไม่ใช่ข้อความที่โมเดลแต่ง)

การ์ดแต่ละใบได้ช่อง `why` ของตัวเอง

```json
"why": {
  "content_similarity": 0.582, "title_similarity": 0.4847, "title_weight": 0.5,
  "blended_score": 0.5334, "percent": 50,
  "percent_floor": 0.35, "percent_ceiling": 0.72, "chunks_used": 5,
  "evidence": [{"file": "cs61.pdf", "page": 112, "similarity": 0.602,
                "excerpt": "อาชีพที่สามารถประกอบได้หลังสำเร็จการศึกษา ได้แก่ นักเขียนโปรแกรม…"}, ...],
  "reason_from_model": true, "no_evidence": false
}
```

ผลทั้งชุดได้ `scoringDetail` (คำตอบที่เข้าเวกเตอร์ / ไม่เข้า) และ `engine.embedding`

```json
"scoringDetail": {
  "queryText": "ชอบวิชา คณิตศาสตร์, คอมพิวเตอร์ สนใจด้าน เทคโนโลยีและคอมพิวเตอร์ ...",
  "answersUsed":      [{"field": "favorite_subjects", "label": "วิชาที่ชอบ", "values": [...]}, ...],
  "answersNotScored": [{"field": "study_track", "label": "สายการเรียน", "values": [...]}, ...],
  "chunksPerCourse": 5
},
"engine": {"explanation": {...}, "scoring": "embedding_and_rules",
           "embedding": {"provider": "ollama", "model": "bge-m3"}}
```

**ตัวเลขทุกตัวเป็นค่าที่ขั้นจัดอันดับคำนวณไปแล้ว** ไม่มีการคิดใหม่ ไม่มีค่าใดมาจากโมเดล และ
หน้าเว็บไม่ได้สร้างตัวเลขเองเลย มีหน้าที่แค่เรียบเรียงถ้อยคำ (`src/lib/scoreDetail.js`)

`excerpt` ตัดมาไม่เกิน 160 ตัวอักษร ยุบช่องว่างทุกชนิดก่อน เพราะข้อความจาก PDF ภาษาไทย
มีขึ้นบรรทัดคั่นกลางคำจนอ่านบนหน้าเว็บไม่ออก · มาจาก chunk ของหลักสูตรใบนั้นในคำสั่ง SQL
เดิม ไม่ได้ถามฐานเพิ่มอีกรอบ

**รุ่นที่เทียบความคล้าย** บันทึกตอน embed สำเร็จลง ContextVar ต่อคำขอ แบบเดียวกับรุ่นที่เขียน
ข้อความ ไม่ได้อ่านจากค่าที่ตั้งไว้ และไม่ได้เก็บบน connector ที่หลายคำขอใช้ร่วมกัน

## 3. ตัวอย่างผลจริง (ฐานทดสอบ + ollama จริง ไม่ใช่ของปลอม)

คำตอบชุด "ชอบคณิตศาสตร์/คอมพิวเตอร์ สนใจเทคโนโลยี ถนัดตรรกะ อยากทำงานบริษัทใหญ่"
เรียก `match_programs` จริงบน `course_advisor_test` (7,301 ชิ้นที่มีเวกเตอร์ · 18 หลักสูตร)

| อันดับ | สาขา | % | เนื้อหา | ชื่อสาขา | หลักฐาน |
|---|---|---|---|---|---|
| 1 | วิทยาการคอมพิวเตอร์ (2561) | 50 | 0.5820 | 0.4847 | `cs61.pdf` หน้า 112, 122, 200, 208, 162 |
| 2 | เทคโนโลยีสารสนเทศ (2566) | 47 | 0.5796 | 0.4707 | `it66.pdf` |
| 3 | คณิตศาสตร์ (2564) | 44 | 0.5616 | 0.4648 | `ma64.pdf` หน้า 89, 139, 12, 89, 34 |
| 4 | เทคโนโลยีผลิตภัณฑ์ชีวภาพฯ (2568) | 43 | 0.5691 | 0.4501 | `bio2568.pdf` หน้า 179, 180, 181, 179, 14 |

ตรวจย้อนกลับใบที่ 1: `0.5 × 0.5820 + 0.5 × 0.4847 = 0.53335` →
`(0.53335 − 0.35) ÷ (0.72 − 0.35) = 0.4956` → **50%** ตรงกับที่แสดง

รอบนี้ผู้เขียนคำอธิบายคือโมเดลในเครื่องตัวเล็ก (qwen2.5:3b) ซึ่งตอบมาผิดรูปแบบ JSON
ทุกใบจึงไม่มีข้อความจาก AI — `engine.explanation` เป็น `null` และ**ทุกใบยังมีคะแนนกับ
รายละเอียดการคำนวณครบ** ซึ่งเป็นกรณี "AI ล่ม" ที่ขอให้ตรวจพอดี

ข้อความต้นฉบับที่ส่งไปแสดงจริงของสองใบแรก

```
cs61.pdf หน้า 112 (0.6020)
  "…0.90 มาก 1.6 อาชีพที่สามารถประกอบได้หลังสำเร็จการศึกษา ได้แก่ นักเขียนโปรแกรม นักวิเคร…"
it66.pdf หน้า 143 (0.5960)
  "143 มคอ. 2 143 ด้านการประเมิน X S.D. แปลผล 3. ด้านการเรียนการสอน 4.15 0.71 มาก…"
```

**ข้อสังเกตที่เห็นได้เพราะมีข้อความต้นฉบับ:** ชิ้นที่ได้ความใกล้เคียงสูงบางชิ้นเป็นตารางผล
ประเมินหรือหัวกระดาษ ไม่ใช่เนื้อหาที่ "ตรงกับคำตอบ" ของผู้ใช้ — ซึ่งเป็นเหตุผลที่รอบนี้เลิก
เรียกส่วนนี้ว่า "จุดที่ตรงกับเนื้อหาหลักสูตร" และเขียนกำกับว่าความใกล้เคียงเชิงข้อความไม่ใช่
การยืนยันข้อเท็จจริง · การจัดอันดับยังเป็นของเดิมทุกประการ รอบนี้แค่ทำให้ตรวจสอบได้

ผลเต็มเป็น JSON อยู่ที่ `sample-real2.json` ในโฟลเดอร์ชั่วคราวของเซสชัน (นอกโปรเจกต์)
