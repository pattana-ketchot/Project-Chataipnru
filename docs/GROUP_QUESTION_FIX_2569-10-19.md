## 2. สาเหตุ

อยู่ที่ `backend/app/services/subjects.py` ฟังก์ชัน `answer_subject_question()`
ซึ่งเป็นด่าน 0.7185 (คำถามรายวิชา) ในลำดับการตัดสินใจของ `services/chat.py`

ฟังก์ชันนี้ตัดสินเป็นสามขั้นตามลำดับ

1. มีรหัสวิชา 7 หลักในคำถาม → ตอบวิชานั้น
2. ถามรายการ **วิชาบังคับ** หรือ **วิชาเลือก** ของหลักสูตร → ตอบเป็นรายการ
3. **จับคู่ด้วยชื่อวิชา** → ตอบวิชาเดียว

คำถามระดับกลุ่มไม่เข้าเงื่อนไขข้อ 2 (ไม่ได้พูดคำว่า "วิชาบังคับ" หรือ "วิชาเลือก")
จึงตกมาถึงข้อ 3 แล้วเจอบรรทัดนี้

```python
hits = [r for r in rows if r["name_th"] and r["name_th"] in question]
```

**ชื่อกลุ่มกับชื่อวิชามีคำซ้ำกัน** — กลุ่มชื่อ "ฝึกประสบการณ์วิชาชีพหรือสหกิจศึกษา"
และมีวิชาชื่อ "สหกิจศึกษา" อยู่ข้างในกลุ่มนั้นพอดี การถามถึง**ชื่อกลุ่ม**จึงถูกตีความว่า
กำลังถามถึง**ชื่อวิชา** แล้วคืนรายละเอียดของวิชาเดียว

ยืนยันด้วยการพิมพ์ผลของตัวจับรูปแบบทุกตัว

```
คำถาม: กลุ่มวิชาฝึกประสบการณ์วิชาชีพหรือสหกิจศึกษา… มีวิชาอะไรบ้าง
  รหัสวิชา=[] · LIST_TAIL=True · บังคับ=False · เลือก=False · ชื่อ=True · หน่วยกิต=False
  >>> ด่านรายวิชาตอบเอง: วิชา 4124815 สหกิจศึกษา …
```

(`ชื่อ=True` เพราะ `_ASKS_NAME` มีคำว่า `วิชาอะไร` ซึ่ง "มีวิชาอะไรบ้าง" เข้าเงื่อนไข)

## 3. ของจริงในเอกสาร — ตรวจจาก cs66.pdf

ข้อความจริงในหน้า 19 ของไฟล์ (หน้าที่พิมพ์ในเล่มคือหน้า 22)

> **2.4) กลุ่มวิชาฝึกประสบการณ์วิชาชีพหรือสหกิจศึกษา ไม่น้อยกว่า 7 หน่วยกิต**
> 4124813 การเตรียมความพร้อมฝึกประสบการณ์วิชาชีพและสหกิจศึกษา … 2(90)
> **ให้เลือกรายวิชาต่อไปนี้ ไม่น้อยกว่า 5 หน่วยกิต**
> 4124814 การฝึกประสบการณ์วิชาชีพวิทยาการคอมพิวเตอร์ … 5(450)
> 4124815 สหกิจศึกษา … 6(540)

คำตอบที่ถูกต้องจึงต้องมีครบ 5 อย่าง

| | |
|---|---|
| หน่วยกิตขั้นต่ำของกลุ่ม | **ไม่น้อยกว่า 7 หน่วยกิต** |
| วิชาที่เรียนแน่นอน | 4124813 (2 หน่วยกิต · 90 ชั่วโมง) |
| เงื่อนไขการเลือก | **เลือกจากสองวิชาถัดไป ไม่น้อยกว่า 5 หน่วยกิต** |
| ตัวเลือกที่ 1 | 4124814 (5 หน่วยกิต · 450 ชั่วโมง) |
| ตัวเลือกที่ 2 | 4124815 (6 หน่วยกิต · 540 ชั่วโมง) |

### เงื่อนไขของกลุ่มไม่ได้อยู่ในข้อมูลที่มีโครงสร้าง

ตรวจ `mko.v_live_values` ของหลักสูตรนี้แล้ว มีเพียง 8 ค่าระดับหลักสูตร
(`total_credits`, `degree_*`, `program_name_*`, `edition_year`, `revision_type`)
**ไม่มีหน่วยกิตขั้นต่ำรายกลุ่ม และไม่มีกติกาการเลือก**

ส่วน `mko.v_live_subjects` มีครบทั้ง 3 วิชาพร้อม `category_path` ของกลุ่ม แต่บอกได้แค่
"มีวิชาอะไรบ้าง" ไม่สามารถบอก "ไม่น้อยกว่า 7" และ "เลือกไม่น้อยกว่า 5" ได้

**ข้อนี้กำหนดรูปแบบของการแก้** — ถ้าให้ตอบรายการจากตารางรายวิชา จะได้รายชื่อครบ
แต่ **ขาดเงื่อนไข** ซึ่งอ่านแล้วเข้าใจผิดได้ง่ายกว่าเดิม จึงต้องปล่อยให้ไปเส้นทางค้นเอกสาร
ที่อ่านหน้า 19 ได้ทั้งหน้า

## 4. สิ่งที่แก้

ไฟล์เดียว: `backend/app/services/subjects.py` (+28 บรรทัด)

### 4.1 เพิ่มตัวแยกคำถามระดับกลุ่ม

```python
_GROUP_WORD = re.compile(r"กลุ่ม|หมวดวิชา")

def _is_group_question(question: str) -> bool:
    return bool(_GROUP_WORD.search(question) and _LIST_TAIL.search(question))
```

**ต้องเข้าเงื่อนไขทั้งสองอย่าง** คือเอ่ยถึงกลุ่ม/หมวด **และ** ถามแบบรายการ
ถ้าถามแค่ "วิชานี้อยู่กลุ่มไหน" ยังเป็นคำถามรายวิชาตามเดิม ไม่ถูกตัวกรองนี้กิน

### 4.2 กันไม่ให้คำถามกลุ่มตกลงไปถึงขั้นจับคู่ด้วยชื่อ

```python
if _is_group_question(question):
    return None          # ไปเส้นทางค้นเอกสาร
```

### 4.3 เพิ่ม "รายชื่อ" และ "กี่วิชา" ใน `_LIST_TAIL`

เดิมมี `รายการ` แต่ไม่มี `รายชื่อ` ซึ่งเป็นคำที่ผู้ใช้ใช้จริงในคำถามที่แจ้งมา

**ไม่ได้แก้ข้อ 1 และข้อ 2** การถามด้วยรหัสวิชาและการถามรายการวิชาบังคับ/วิชาเลือก
ทำงานเหมือนเดิมทุกประการ

## 7. สิ่งที่พบเพิ่มระหว่างตรวจ — **ยังไม่ได้แก้**

### 7.1 ข้อมูล `requirement` ของ 4124813 ไม่ตรงกับเอกสาร

ในฐานข้อมูล ทั้งสามวิชามี `requirement = choose_group` ซึ่งแสดงผลเป็น
"วิชาในกลุ่มที่ต้องเลือกให้ครบหน่วยกิตขั้นต่ำ"

แต่เอกสารวางบรรทัด "ให้เลือกรายวิชาต่อไปนี้ ไม่น้อยกว่า 5 หน่วยกิต" ไว้ **หลัง** 4124813
กติกาการเลือกจึงใช้กับ 4124814 และ 4124815 เท่านั้น ส่วน **4124813 เป็นวิชาที่ต้องเรียน**
(2 + อย่างน้อย 5 = ไม่น้อยกว่า 7 ซึ่งตรงกับหัวข้อกลุ่มพอดี)

ผลคือถ้าถาม "วิชา 4124813 เป็นวิชาบังคับไหม" จะได้ป้ายกำกับที่ชวนเข้าใจผิด

**เป็นปัญหาของข้อมูลที่สกัดมา ไม่ใช่ของเส้นทางคำถาม** และการแก้ต้องไปแก้ที่สายงานสกัด
แล้วเผยแพร่ใหม่ ซึ่งแตะข้อมูล production — **ไม่ได้ทำในรอบนี้ตามที่สั่ง**

### 7.2 คำตอบอ้าง `cs66_brief.pdf` ขณะที่ข้อความจริงอยู่ใน `cs66.pdf`

สำนวนที่ 1 ได้คำตอบถูกต้อง แต่ชั้นตรวจหลักฐานต่อท้ายว่า

```
ที่มา (ตรวจแล้วรองรับบางส่วน): cs66_brief.pdf หน้า 31
ยังยืนยันไม่ได้จากหน้าที่อ้าง: ไม่น้อยกว่า 7 หน่วยกิต
```

เพราะหน้าที่ถูกอ้างมาจากเอกสารอีกเล่ม ส่วนข้อความ "ไม่น้อยกว่า 7 หน่วยกิต" อยู่ใน
`cs66.pdf` หน้า 19 ระบบจึงรายงานอย่างตรงไปตรงมาว่ายืนยันจากหน้าที่อ้างไม่ได้
— **ชั้นตรวจทำงานถูกต้อง** แต่การเลือกหน้ามาอ้างยังเลือกได้ไม่ดีที่สุด

เป็นคนละเรื่องกับบั๊กนี้ และควรดูแยกต่างหากว่าจะจัดลำดับความสำคัญของเอกสารฉบับเต็ม
เหนือฉบับย่อหรือไม่ **ยังไม่ได้แก้**
