### 1.3 ปัญหาที่พบและแก้ระหว่างทาง (รายงานตามจริง)

**ก. เครื่องหมายขึ้นบรรทัดแบบ Windows ปนเข้า `.env`**

ตอนขั้นที่ 2 ผมเตรียมบรรทัดจากเครื่อง Windows แล้วต่อท้าย `.env` ผลคือ **ทั้ง 7 บรรทัดที่เพิ่มมี CR ติดไปด้วย**
ทำให้ค่า `VITE_SUPABASE_URL` ยาวเกินไป 1 ไบต์ และ `GOOGLE_GENERATIVE_AI_API_KEY` ที่ควรว่างกลับมีความยาว 1

แก้แล้วโดยตัด CR เฉพาะบรรทัดที่ 21 เป็นต้นไป (บรรทัดที่ผมเพิ่ม) ตรวจซ้ำแล้ว:
20 บรรทัดแรก **เหมือนของเดิมทุกไบต์** · ค่าทั้งสามถูกต้อง (40 ไบต์ · 208 ไบต์ · ว่าง)
สำรองไฟล์ก่อนแก้ไว้ที่ `env.before_step2` และ `env.before_crfix`

**ข. ผมตรวจ CR ด้วยวิธีที่ผิดในครั้งแรก**

ใช้ `grep $"\r"` ซึ่งในเชลล์ไม่ได้แปลว่า CR แต่กลายเป็นการค้นตัวอักษร `r` จึงรายงานผลผิด
ตรวจใหม่ด้วย Python แล้วได้ข้อเท็จจริงคือ **ไฟล์เดิมไม่มี CR เลย** ส่วนบรรทัดที่ผมเพิ่มมีทุกบรรทัด

**ค. Caddyfile เปลี่ยนรูปแบบขึ้นบรรทัดทั้งไฟล์**

การแก้ด้วย Python ทำให้ไฟล์เดิมที่เป็น CRLF ทั้ง 58 บรรทัดกลายเป็น LF ทั้งหมด
Caddy ไม่สนใจเรื่องนี้ (validate ผ่าน) แต่ทำให้ diff อ่านไม่รู้เรื่อง
**คืนรูปแบบเป็น CRLF แล้ว** ตอนนี้ diff แสดงเฉพาะ **16 บรรทัดที่เพิ่ม** ไม่มีบรรทัดเดิมถูกแตะ

**ง. `caddy validate` แจ้ง error ตอนแรก**

ข้อความคือ `unrecognized global option: handle` เกิดจากผมรัน validate โดยไม่ได้ตั้ง `SITE_DOMAIN`
บล็อกแรกจึงไม่มีชื่อเว็บและถูกอ่านเป็นบล็อกตั้งค่าส่วนกลาง — เป็นกับดักเดียวกับที่คอมเมนต์ในไฟล์เตือนไว้
ตั้งค่าให้เหมือนตอนรันจริงแล้ว validate ได้ **Valid configuration** ทั้งไฟล์ใหม่และไฟล์เดิม
