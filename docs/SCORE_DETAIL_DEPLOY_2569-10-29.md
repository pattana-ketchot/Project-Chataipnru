## 2. ตรวจรับบนเว็บจริง — response กับหน้าจอของ **คำขอเดียวกัน**

ดัก `fetch` ไว้ก่อนให้หน้าผลลัพธ์ยิงคำขอ แล้วอ่าน DOM ของคำขอนั้น ไม่ได้เอาคนละคำขอมาเทียบกัน
(bundle ที่หน้านั้นโหลด: `index-CH6CB5kB.js` · คำขอ 200 · เวลา 12:03:07Z)

| การ์ด | % บนหัวการ์ด | `why` ใน response | สูตรบนหน้าจอ | ไฟล์/หน้าบนหน้าจอ |
|---|---|---|---|---|
| วิทยาการคอมพิวเตอร์ (อันดับหลัก) | 50% | 0.5820 / 0.4847 → 0.5334 → 50 | `0.58 × 0.50 + 0.48 × 0.50 ≈ 0.53` → ≈ 50% | `cs61.pdf` 112, 122, 200, 208, 162 |
| เทคโนโลยีสารสนเทศ (ทางเลือก) | 47% | 0.5805 / 0.4707 → 0.5256 → 47 | `0.58 × 0.50 + 0.47 × 0.50 ≈ 0.53` → ≈ 47% | `it66.pdf` 143, 98, 148 · `it66_brief.pdf` 28 · `it66.pdf` 58 |
| คณิตศาสตร์ (ทางเลือก) | 44% | 0.5613 / 0.4648 → 0.5130 → 44 | `0.56 × 0.50 + 0.46 × 0.50 ≈ 0.51` → ≈ 44% | `ma64.pdf` 89, 139, 12, 89, 34 |

* เปอร์เซ็นต์บนหัวการ์ด = `why.percent` ของใบนั้น **ทุกใบ**
* ความใกล้เคียงรายชิ้นบนหน้าจอตรงกับ `evidence[].similarity` ของใบตัวเอง ทุกบรรทัด
* ข้อความต้นฉบับที่แสดงตรงกับ `excerpt` ของชิ้นนั้น ไม่สลับชิ้นและไม่สลับการ์ด
* ไฟล์ของแต่ละใบเป็นเอกสารของสาขาใบนั้น ไม่มีไฟล์ของสาขาอื่นโผล่ข้ามใบ
* ทุกใบมีบรรทัดจำกัดคะแนน `ค่าที่ต่ำกว่า 0.35 นับเป็น 0% และสูงกว่า 0.72 นับเป็น 100%…`
* ช่อง "ส่วนที่ยังไม่พบข้อมูลเชื่อมโยง" ของรอบนี้ขึ้นสองบรรทัดที่วัดได้จริง (สายการเรียนและ
  สภาพแวดล้อมการทำงานไม่ได้ถูกใช้คิดคะแนน) **ไม่มีบรรทัดที่เอา 0.35 ไปตัดสินรายองค์ประกอบ**

**ชื่อโมเดลบนหน้าจอ** ตรงกับ `engine` ใน response ของคำขอเดียวกัน

## 3. ข้อจำกัดของ "เนื้อหาที่ใช้เทียบ" ที่ผู้ใช้กำลังจะเห็น

เรื่องนี้สำคัญกว่าการแสดงผลสวยงาม เพราะผู้ใช้จะเริ่มอ่านข้อความจากเอกสารโดยตรง

1. **ส่วนที่แสดงคือ 5 ชิ้นที่เวกเตอร์ใกล้ที่สุด ไม่ใช่ "ข้อความที่พิสูจน์ว่าเหมาะ"** — จากผลจริง
   รอบนี้ ชิ้นที่ได้คะแนนสูงสุดของเทคโนโลยีสารสนเทศคือ **ตารางผลประเมินความพึงพอใจ**
   (`it66.pdf` หน้า 143) และของวิทยาการคอมพิวเตอร์ชิ้นแรกขึ้นต้นด้วยเศษตัวเลขจากตาราง
   หน้าเว็บจึงเขียนกำกับไว้ว่าความใกล้เคียงเชิงข้อความ **ไม่ใช่การยืนยันว่าเนื้อหาตรงกับคำตอบ**
2. **หนึ่งการ์ดอาจมีหลายไฟล์ของสาขาเดียวกัน** — เช่นเทคโนโลยีสารสนเทศมีทั้ง `it66.pdf`
   และ `it66_brief.pdf` ซึ่งเป็นเอกสารคนละฉบับของหลักสูตรเดียวกัน ไม่ใช่ข้ามสาขา
3. **ข้อความตัดที่ 160 ตัวอักษรจากกลางชิ้น** จึงมักขึ้นต้นและจบกลางประโยค และมีเศษ
   เลขหน้า/หัวกระดาษติดมา เพราะเป็นข้อความที่สกัดจาก PDF ตามจริง ไม่ได้ขัดเกลา
4. **ตัวเลขในสูตรปัดเหลือสองตำแหน่ง** จึงใช้ `≈` — คิดตามเลขที่เห็นจะได้ค่าใกล้เคียง
   ไม่ใช่ค่าที่ระบบใช้จริงแบบเป๊ะ ๆ
5. **คำอธิบายของ AI ยังผ่านด่านตรวจข้อความอ้างอิงแยกต่างหากเหมือนเดิม** — ส่วน
   "ทำไมได้คะแนนนี้" ไม่ได้ผ่านด่านนั้นเพราะไม่มีข้อความที่โมเดลแต่งอยู่เลย เป็นค่าที่คำนวณล้วน

## 5. ที่ยังไม่ได้ทำ

  ทดสอบแล้ว แต่ยังไม่มีสำเนานอกเครื่อง

* ไม่ได้รันชุดใหญ่ซ้ำตามที่สั่ง (ชุดที่ต้องใช้ฐานจริงและโมเดลจริง)
