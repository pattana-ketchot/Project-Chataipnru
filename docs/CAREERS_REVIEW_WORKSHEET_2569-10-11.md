## 1. ⚠ ผมไม่ได้เขียนรายการอาชีพของหลักสูตรใดขึ้นมาเอง

| ข้อ | เหตุผล |
|---|---|
| ไฟล์ มคอ.2 **ไม่มีในเครื่องพัฒนา** | ไม่มีโฟลเดอร์ `documents/` และหา `.pdf` ในรีโปไม่เจอเลย — ของจริงอยู่บนเซิร์ฟเวอร์ที่ `./documents` ซึ่ง mount เป็น `/srv/documents:ro` |
| เขียนจากคำบรรยายในหน้าเว็บแทนไม่ได้ | ข้อความนั้นมาจากหน้าเว็บทางการของ PNRU ไม่ใช่ มคอ.2 จึง **อ้างชื่อไฟล์และเลขหน้าไม่ได้** |
| แยกอาชีพออกจากข้อความร้อยแก้วไม่ได้ | เป็นการตีความ ไม่ใช่การยกมา |

**สิ่งที่เตรียมให้แทน** — ขั้นตอนและคำสั่งที่ดึงรายการอาชีพ **ที่ตัวสกัดอ่านจากเอกสารจริงไว้แล้ว** ออกมาพร้อมชื่อไฟล์ เลขหน้า และข้อความที่ยกมา เพื่อให้คนตรวจรับ

> ระบบมีด่านบังคับอยู่แล้วว่า **ข้อความที่ยกมาต้องปรากฏอยู่ในหน้าที่อ้างจริง** (trigger `mko.check_evidence_quote` ใน `db/migrations/001_mko_structured.sql`) จึงไม่มีทางมีหลักฐานที่ชี้ไปหน้าที่ไม่มีข้อความนั้น

## 2. สำรวจก่อนว่ามีอะไรอยู่แล้ว — อ่านอย่างเดียว

### 2.1 เผยแพร่แล้วกี่หลักสูตร

```sql
select c.title, count(*) as items, min(i.page_start) as page, max(i.source_filename) as file
from mko.v_live_list_items i join public.courses c on c.id = i.course_id
where i.item_type = 'career'
group by c.title order by c.title;
```

**คาดว่าได้ 2 แถว** — ถ้าได้มากกว่านั้นแปลว่ามีการเผยแพร่เพิ่มหลังรายงาน P1

### 2.2 มีรายการอาชีพที่สกัดไว้แล้วแต่ยังไม่เผยแพร่ กี่หลักสูตร

```sql
select c.title, i.status, count(*) as items
from mko.list_items i
  join mko.curricula cu on cu.id = i.curriculum_id
  join public.courses c on c.id = cu.course_id
where i.item_type = 'career'
group by c.title, i.status order by c.title, i.status;
```

| สถานะที่เห็น | แปลว่า |
|---|---|
| `verified` | **ตรวจแล้ว พร้อมเผยแพร่** — ไปข้อ 4 ได้เลย |
| `candidate` | ตัวสกัดอ่านมาได้แต่ **ยังไม่มีคนตรวจ** — ต้องทำข้อ 3 |
| `needs_review` | ตัวสกัดไม่มั่นใจ — ต้องทำข้อ 3 |
| `rejected` | คนตรวจแล้วว่าไม่ถูก — **ห้ามเผยแพร่** |
| ไม่มีแถวของหลักสูตรนั้นเลย | ยังไม่เคยสกัด — ดูข้อ 5 |

### 2.3 ดูรายการพร้อมหลักฐานของหลักสูตรหนึ่ง

```sql
select i.seq, i.text, i.status, d.original_filename as file, e.page_start, e.page_end, left(e.quote, 200) as quote
from mko.list_items i
  join mko.evidence e on e.id = i.evidence_id
  join public.course_documents d on d.id = i.document_id
  join mko.curricula cu on cu.id = i.curriculum_id
  join public.courses c on c.id = cu.course_id
where i.item_type = 'career' and c.title like '%ชีววิทยา%'
order by i.seq;
```

> เปลี่ยนคำใน `like` เป็นชื่อหลักสูตรที่ต้องการ · **ห้าม `select *`** จากตารางเหล่านี้ไม่จำเป็น แต่ `quote` ยาวมาก จึงตัดด้วย `left()`

## 3. ขั้นตรวจรับ — ใช้เครื่องมือที่มีอยู่ ไม่ต้องสร้างใหม่

### 3.1 ดูสถานะรวม

```bash
python -m pipeline.mko.review status
```

### 3.2 ส่งออกคิวเป็น CSV ให้คนตรวจ

```bash
python -m pipeline.mko.review export --out backups/mko_local/review_queue_careers.csv
```

ไฟล์เป็น CSV UTF-8 BOM เปิดใน Excel ได้ · **หนึ่งแถวต่อหนึ่งค่า มีค่าที่สกัดได้ เลขหน้า และข้อความที่ยกมา** ครบตามที่ต้องการให้ตรวจรับ

### 3.3 คนตรวจกรอกช่อง `decision`

| กรอกอะไร | ความหมาย |
|---|---|
| `verified` หรือ `ผ่าน` | ตรงกับเอกสาร |
| `rejected` หรือ `ไม่ผ่าน` | ไม่ตรง |
| เว้นว่าง | ยังไม่ตัดสิน — **แถวนั้นไม่ถูกแตะ** |

### 3.4 นำผลตรวจกลับเข้าระบบ

```bash
python -m pipeline.mko.review apply --file backups/mko_local/review_queue_careers.csv --reviewer "ชื่อผู้ตรวจ"
```

ผู้ตรวจที่เป็นคนถูกบันทึกเป็น `reviewed_by = "human:<ชื่อ>"` แยกจากกฎอัตโนมัติ (`auto:...`) ได้เสมอ

## 4. ขั้นเผยแพร่ — ต้องตัดสินใจเรื่องนโยบายก่อน

### 4.1 ⚠ ข้อตัดสินใจที่สำคัญ

การเผยแพร่ครั้งล่าสุด (P1) ใช้นโยบาย **`verified_any`** คือรับทั้งค่าที่กฎอัตโนมัติยืนยันและค่าที่คนตรวจ

แต่เอกสารของเครื่องมือระบุไว้เองว่า

> `verified_human_only` (`--human-only`) เฉพาะค่าที่คนตรวจแล้ว — **ควรใช้ก่อนเปิดคำตอบให้ผู้ใช้จริง**

**รอบนี้ต่างจากเดิม** เพราะหน้า "อาชีพหลังจบ" จะแสดงรายการเหล่านี้ **ให้คนทั่วไปเห็นบนหน้าเว็บ** ไม่ใช่โหมด shadow อีกต่อไป

| ทาง | คำสั่ง | ข้อแลก |
|---|---|---|
| **ก (แนะนำ)** | `--human-only` | ขึ้นเฉพาะที่คนตรวจแล้ว · อาจได้น้อยกว่า แต่ทุกข้อมีคนรับรอง |
| ข | ไม่ใส่ธง | ได้มากกว่า · แต่บางข้อมีแต่กฎอัตโนมัติรับรอง ซึ่งจะไปแสดงต่อสาธารณะ |

> **ถ้าเลือกทาง ก อาจทำให้ 2 หลักสูตรที่เผยแพร่อยู่ตอนนี้หายไปจากหน้าเว็บ** ถ้ารายการของมันถูกยืนยันด้วยกฎอัตโนมัติ — ตรวจด้วยข้อ 4.2 ก่อนตัดสินใจ

### 4.2 ตรวจก่อนว่าใครรับรองรายการที่เผยแพร่อยู่

```sql
select c.title, i.reviewed_by, count(*) as items
from mko.v_live_list_items i join public.courses c on c.id = i.course_id
where i.item_type = 'career'
group by c.title, i.reviewed_by order by c.title;
```

ถ้า `reviewed_by` ขึ้นต้นด้วย `human:` ทั้งหมด → ทาง ก ปลอดภัย

### 4.3 ลองก่อนไม่ลงมือจริง

```bash
python -m pipeline.mko.publish --by "ชื่อผู้เผยแพร่" --human-only --dry-run
```

อ่านผลให้ครบว่าจะได้กี่หลักสูตร กี่ข้อ และมีค่าเดิมหายไปไหม

### 4.4 เผยแพร่จริง

```bash
python -m pipeline.mko.publish --by "ชื่อผู้เผยแพร่" --human-only
```

### 4.5 ย้อนกลับ

```bash
python -m pipeline.mko.publish --by "ชื่อผู้เผยแพร่" --rollback-latest
```

การเผยแพร่แต่ละครั้งเป็นภาพถ่ายใหม่ และ `v_live_*` ชี้ไปที่ครั้งล่าสุด **การลบครั้งล่าสุดจึงกลับไปใช้ครั้งก่อนหน้าทันที**

### 4.6 ตรวจผลหลังเผยแพร่

```sql

  join public.courses c on c.id = i.course_id

```

## 5. ถ้าหลักสูตรใดยังไม่เคยสกัด

ขั้นสกัดอยู่ที่ `python -m pipeline.mko.run` และต้องมีไฟล์ มคอ.2 ของหลักสูตรนั้นอยู่ในระบบแล้ว

| # | ตรวจก่อน | คำสั่ง |
|---|---|---|
| 1 | หลักสูตรนั้นมีเอกสารในระบบไหม | `select c.title, d.original_filename from public.course_documents d join public.courses c on c.id = d.course_id order by c.title;` |
| 2 | ถ้าไม่มีเอกสาร | ต้องนำเข้าเอกสารก่อน — **เป็นงานคนละเรื่องและใหญ่กว่ารอบนี้** |

> รอบก่อนพรีหน้าที่ 1 สัปดาห์ **การสกัดหลักสูตรใหม่ตั้งแต่ต้นมีความเสี่ยงสูง** ถ้าข้อ 2.2 บอกว่าหลักสูตรใดไม่มีแถวเลย แนะนำให้ **ปล่อยให้หน้าเว็บขึ้นว่ายังไม่มีรายการที่ตรวจแล้ว** ซึ่งเป็นพฤติกรรมที่โค้ดรองรับอยู่แล้ว

## 6. ความครอบคลุมที่จะได้ กับที่หน้าเว็บจะแสดง

| กรณี | หน้า `/careers` แสดงอะไร |
|---|---|
| เผยแพร่ 2 หลักสูตร (สภาพปัจจุบัน) | 2 การ์ดมีรายการ + ปุ่มเปิดเอกสาร · อีก 10 การ์ดขึ้นว่ายังไม่มีรายการที่ตรวจแล้ว · บรรทัดบอก "2 จาก 12 หลักสูตร" |
| เผยแพร่เพิ่มเป็น N | N การ์ดมีรายการ · บรรทัดเปลี่ยนเป็น "N จาก 12" เอง |
| ไม่เผยแพร่เพิ่มเลย | ยังใช้งานได้และไม่ดูพัง — แต่ตอนพรีจะเห็นแค่ 2 หลักสูตร |

**หน้าเว็บไม่ต้องแก้อีกเมื่อข้อมูลเพิ่ม** — ตัวเลขและการจัดเรียงคิดจากข้อมูลที่ได้มาจริง
