## 2. คำตอบตรงคำถาม

**2.1 classify เป็น intent อะไร** — "ขอคำแนะนำสาขา" (recommendation) ซึ่ง **ตรงตามพรอมต์ที่ออกแบบไว้** ไม่ใช่การจำแนกผิด: `RECOMMEND_INTENT_SYSTEM_PROMPT` (`llm/prompts.py:271`) ระบุว่าข้อความทำนอง "ยังไม่รู้จะเรียนอะไร / ขอให้ช่วยเลือกสาขาให้" ให้ตอบ `true`

**2.2 interest ที่ส่งเข้า match_programs** — `{"extra": "เรียนไรดี"}` และข้อความที่ถูกแปลงเป็นเวกเตอร์คือ `"เรียนไรดี"` ทั้งประโยค
- log ไม่ได้เก็บค่า `interest` ที่โมเดลคืนมา จึงยืนยันไม่ได้ 100% ว่าโมเดลคืน `""` แล้วโค้ดแทนที่ด้วยทั้งประโยค (chat.py:545) หรือโมเดลคัด `"เรียนไรดี"` มาเอง — **ผลลัพธ์ที่ส่งเข้า ranking เหมือนกันทั้งสองทาง**

**2.3 มี validation ว่า interest มีข้อมูลพอไหม — ไม่มี** ด่านที่มีอยู่ทั้งหมดเป็นการตรวจ "รูปแบบ" ไม่ใช่ "สาระ"

| ด่านที่มี | ตรวจอะไร | ผลกับ "เรียนไรดี" |
|---|---|---|
| `chat.py:545` | interest ต้องเป็นข้อความย่อยของคำถาม | ไม่ผ่าน → ใช้ทั้งประโยคแทน (ไม่ได้ปฏิเสธ) |
| `chat.py:551` | เหลืออะไรนอกจากชื่อสาขาไหม | ผ่าน เพราะมีอักษรไทย |
| `program_match.py:461` | `query_text.strip()` ต้องไม่ว่าง | ผ่าน เพราะมีข้อความ |
| `_close_to_best` | คะแนนห่างอันดับ 1 ไม่เกิน 0.04 | เป็นเกณฑ์ "สัมพัทธ์" ไม่มีขั้นต่ำสัมบูรณ์ |

**2.4 ทำไมจึงเข้าสู่ ranking ได้ทั้งที่ไม่มี preference**
- ระบบให้คะแนน **ทุกหลักสูตรเสมอ** แล้วเรียงลำดับ ไม่ว่าข้อความจะมีสาระหรือไม่
- เกณฑ์คัดเป็นแบบสัมพัทธ์ล้วน (ห่างจากอันดับ 1 ไม่เกิน 0.04) ไม่มี "คะแนนขั้นต่ำ" จึงมีอันดับ 1 เสมอ และมักมีเพื่อนบ้านติดมาด้วย
- โค้ดเองบันทึกการวัดไว้แล้วว่าโปรไฟล์ที่จงใจตอบกว้าง ("ยังไม่รู้ว่าชอบอะไร") ได้อันดับ 1 ที่ **24%** เทียบกับ 55–72% ของโปรไฟล์ที่ชัดเจน (`program_match.py` docstring) — สัญญาณว่า "ข้อมูลไม่พอ" มีอยู่ในคะแนน แต่ไม่เคยถูกนำมาใช้ตัดสินใจ

## 4. คำถามกลุ่มเดียวกัน — กฎรวม ไม่ใช่การจับทีละประโยค

ไม่มี string matching รายประโยคในโค้ดเลย การจัดเส้นทางทำโดยตัวจำแนกเชิงความหมาย (`RECOMMEND_INTENT_SYSTEM_PROMPT`) ดังนั้นทุกข้อความต่อไปนี้จะถูกจัดเป็น recommendation เหมือนกันหมด

|---|---|---|---|
| "เรียนไรดี" / "เรียนอะไรดี" | recommendation | ไม่มี | จัดอันดับทันที (log ยืนยันแล้ว) |
| "แนะนำสาขาหน่อย" / "ช่วยเลือกสาขาให้หน่อย" | recommendation | ไม่มี | คาดว่าเหมือนกัน (ยังไม่มี log) |
| "ไม่รู้จะเรียนอะไร" | recommendation (พรอมต์ระบุตรงตัว) | ไม่มี | คาดว่าเหมือนกัน |
| "มีสาขาไหนน่าเรียน" | recommendation | ไม่มี | คาดว่าเหมือนกัน |

**กฎที่หายไปคือ:** ระบบแยก "เจตนา" (ขอคำแนะนำ) ออกจาก "ข้อมูลที่พอจะแนะนำได้" ไม่ได้ — มีแค่ด่านแรก ไม่มีด่านหลัง
ทั้งสองกลุ่มในตารางเป็น recommendation เหมือนกัน ต่างกันที่มี preference หรือไม่ ซึ่งเป็นสิ่งที่ควรเป็นตัวตัดสินว่าจะ "ถามต่อ" หรือ "จัดอันดับ"

## 5. พฤติกรรมที่ควรเป็น

เมื่อเป็น recommendation แต่ไม่มี preference ที่ใช้ได้ ระบบควร
1. **ถามกลับก่อน** ว่าชอบวิชาอะไร สนใจด้านไหน ถนัดอะไร หรืออยากทำงานแบบไหน
2. **ยังไม่เรียก `match_programs`** เพราะการจัดอันดับจากข้อความที่ไม่มีสาระให้ผลที่อธิบายไม่ได้ (และเปลือง embedding + Gemini หนึ่งครั้งต่อคำถาม)
3. ข้อความที่ถามกลับควรใช้ถ้อยคำเดียวกับคำถามต่อยอดที่มีอยู่แล้ว (`_FOLLOW_UP_LEAD`) เพื่อให้เทิร์นถัดไปเข้าเส้นทาง `_refinement_of_recommendation` และนำคำตอบไปจับคู่ได้ทันที **โดยไม่ต้องสร้างกลไกใหม่**
4. ควรเสนอทางเลือกให้ผู้ใช้ที่ยังตอบไม่ได้จริง ๆ เช่น บอกว่าถามรายชื่อสาขาทั้งหมดก็ได้ (`asks_for_program_list` มีอยู่แล้ว)

## 7. ต้อง train หรือ fine-tune โมเดลไหม — ไม่

- ตัวจำแนกทำงาน**ถูกตามสเปกแล้ว** ("ขอให้ช่วยเลือก" = recommendation) ปัญหาไม่ได้อยู่ที่ความแม่นของโมเดล
- สิ่งที่ขาดคือ **ด่านตรวจฝั่งโค้ด** ว่ามี preference พอจะจัดอันดับหรือยัง ซึ่งเป็น rule ธรรมดา
- การแก้พรอมต์ก็ไม่จำเป็นในขั้นต่ำ เพราะพรอมต์กำหนดไว้แล้วว่าให้คัด "ส่วนที่บอกความสนใจ" มา และให้ `interest` ว่างเมื่อไม่มี — โค้ดเพียงแต่ไม่ได้ใช้สัญญาณนั้น กลับแทนที่ด้วยทั้งประโยค (`chat.py:545`)

## 8. Minimal fix ที่เสนอ (ยังไม่ทำ)

**แนวทางหลัก — ใช้สัญญาณที่มีอยู่แล้วจากขั้นจำแนกเจตนา**
- ที่ `chat.py:545`: เมื่อ `interest` ที่โมเดลคืนมา "ว่าง" หรือ "ไม่ใช่ข้อความย่อยของคำถาม" ปัจจุบันแทนที่ด้วยทั้งประโยค → เปลี่ยนเป็นส่งสัญญาณว่า **ไม่มี preference**
- ที่ `chat.py:1147`: เมื่อได้สัญญาณนั้น ตอบด้วยข้อความถามกลับคงที่ (ใช้ `_FOLLOW_UP_LEAD` เดิม) โดย **ไม่เรียก `match_programs`**
- ไม่ใช้รายการคำ ("เรียนไรดี", "แนะนำสาขาหน่อย", …) เพราะประวัติของโปรเจกต์นี้วัดแล้วว่ารายการคำไม่มีวันครบ (ดู docstring ของ `_recommendation_intent`)
- **ข้อจำกัดของหลักฐาน:** ยังไม่ยืนยันว่าโมเดลคืน `interest = ""` จริงสำหรับข้อความกลุ่มนี้ เพราะไม่มี log — ต้องมี **controlled test 2–3 คำขอ** ก่อนลงมือ ถ้าโมเดลคืนทั้งประโยคมาเอง แนวทางนี้จะไม่ทำงานและต้องใช้แนวทางสำรอง

**แนวทางสำรอง (ถ้าแนวทางหลักไม่ผ่านการทดสอบ) — เกณฑ์คะแนนขั้นต่ำ**
- ใช้คะแนนดิบของอันดับ 1 เป็นตัวตัดสิน โดยอิงค่าที่วัดไว้แล้ว (โปรไฟล์กว้าง 24% เทียบกับโปรไฟล์ชัด 55–72%) เช่น ถ้าอันดับ 1 ต่ำกว่าเกณฑ์ ให้ถามกลับแทนการแสดงรายการ
- ข้อเสีย: ต้องเรียก `match_programs` ก่อน จึงยังเสีย embedding + Gemini หนึ่งครั้ง และการตั้งเกณฑ์ต้องมีชุดวัดรองรับ
- ไม่เปลี่ยน margin/limit/สูตร เพราะเป็นการตัดสินใจ "แสดงหรือถาม" หลังได้คะแนนแล้ว
