## 1. ‼ ข้อบังคับเรื่องลำดับ deploy

> **หน้าเว็บที่แก้รอบนี้ไม่คุยกับ Supabase เรื่องหลักสูตรอีกแล้ว** ถ้า deploy หน้าเว็บก่อนที่ข้อมูลจะเข้า `web.site_courses` และ backend ขึ้นเส้นทางใหม่ **หน้าสาธารณะเกือบทั้งเว็บจะว่าง**

ลำดับที่ห้ามสลับ

```
1. deploy backend  (เส้นทาง /site/courses)
2. นำข้อมูลเข้า    (pipeline.web.import_from_supabase --apply)
3. ตรวจ           /api/site/courses ต้องได้ 12 หลักสูตร
4. deploy หน้าเว็บ
```

ย้อนกลับ: **ย้อนหน้าเว็บก่อน** แล้วค่อยย้อน backend · ข้อมูลใน `web.*` ทิ้งไว้ได้ ไม่มีใครอ่านถ้าหน้าเว็บย้อนแล้ว

## 2. เสร็จแล้วรอบนี้

### 2.1 ขั้นนำข้อมูลเข้า

| ไฟล์ | หน้าที่ |
|---|---|
| `pipeline/web/import_from_supabase.py` | อ่าน Supabase ต่อฐานข้อมูลตรง → เขียน `web.*` ห้าตาราง |
| `pipeline/web/programme_links.json` | ตารางจับคู่หลักสูตรสองฝั่งที่ยืนยันแล้ว 12 รายการ (สร้างจาก `programmeLinks.js` ของหน้าเว็บ) |
| `eval/web_import_check.py` | **29 ข้อ ผ่านหมด** |

**การตัดสินใจที่สำคัญในสคริปต์นี้**

| เรื่อง | ทำอย่างไร | ทำไม |
|---|---|---|
| อ่านจากต้นทาง | **ต่อ PostgreSQL ตรง ไม่ผ่าน PostgREST** | RLS ซ่อนข่าวร่าง และ C1 จำกัด `user_profiles` — อ่านผ่าน API จะได้ไม่ครบโดยไม่มีอะไรเตือน |
| รหัสแถว | **ใช้ id ของต้นทางเป็น id ปลายทาง** | รันซ้ำได้ (upsert) และ **ลิงก์ `/courses/<id>` ที่คนเคยบันทึกไว้ยังเปิดได้เหมือนเดิม** |
| `course_id` | จับคู่จากตารางที่ยืนยันแล้วเท่านั้น · ชื่อชี้ไปหลายหลักสูตร = ไม่จับคู่ | จับคู่ผิดคือหน้าเว็บแสดงเอกสารของสาขาอื่น |
| `created_by`/`updated_by` | แปลงผ่าน `public.users.supabase_user_id` · หาไม่เจอเป็น NULL | ตามที่ 005 ระบุ "ปล่อย NULL ดีกว่ายัดเจ้าของผิดคน" |
| ชื่อคอลัมน์ 3 คู่ | `logo`→`logo_url` · `date`→`published_on` · `image`→`image_url` | แปลงพลาดคือรูปหายทั้งเว็บโดยไม่มี error |
| ความปลอดภัย | ทุก select อ่านจาก `public.` ของต้นทาง · ทุก insert เขียนลง `web.` เท่านั้น · ไม่มี `drop`/`truncate`/`alter`/`delete` | มีข้อทดสอบบังคับไว้ |

**ข้อสำคัญที่สุดของเส้นทางนี้** — อ่านฐานข้อมูลไม่ได้ต้องตอบ **`503`** ไม่ใช่รายการว่าง เพราะรายการว่างทำให้หน้าเว็บขึ้นว่า "ยังไม่มีหลักสูตร" ทั้งที่จริงคือระบบมีปัญหา

และกรอง `is_published` ทุกคำขอ เพราะการกรองนี้ย้ายจาก RLS มาอยู่ที่โค้ดแล้ว ลืมเมื่อไรของที่ยังไม่พร้อมหลุดออกสาธารณะ

## 4. วิธีรันขั้นนำข้อมูลเข้า

ตั้งค่าสองตัวนี้ก่อน **ไม่ต้องใส่ในคำสั่ง และไม่มีอะไรพิมพ์ค่าออกมา**

| ตัวแปร | คืออะไร |
|---|---|
| `SUPABASE_DB_URL` | connection string ของ PostgreSQL ที่ Supabase ให้ (Dashboard → Project Settings → Database) |
| `DATABASE_URL` | ของฐานข้อมูลปลายทาง — มีอยู่แล้วใน `.env` ของเซิร์ฟเวอร์ |

```bash
python -m pipeline.web.import_from_supabase --dry-run
```

อ่านผลให้ครบก่อน — จำนวนแถวแต่ละตาราง · จับคู่หลักสูตรได้กี่รายการ · หลักสูตรไหนยังไม่มี `course_id`

```bash
python -m pipeline.web.import_from_supabase --apply
```

ตรวจผล

```sql
select 'site_courses' t, count(*) from web.site_courses
union all select 'news', count(*) from web.news
union all select 'external_news', count(*) from web.external_news
union all select 'knowledge_articles', count(*) from web.knowledge_articles
union all select 'ai_settings', count(*) from web.ai_settings;
```

```sql
select count(*) filter (where course_id is not null) as จับคู่ได้, count(*) as ทั้งหมด
from web.site_courses;
```

> **รันซ้ำได้ปลอดภัย** — เป็น upsert ตาม id ไม่สร้างแถวซ้ำ
