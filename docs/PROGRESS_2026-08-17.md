## 2. ปัญหาที่พบและวิธีแก้

### 2.1 ค้นหาไม่พบเนื้อหาที่มีอยู่จริง

**อาการ** ผู้ใช้ถาม "สาขาวิชาเทคโนโลยีการจัดการสุขภาพ เรียนจบทำอาชีพไหนได้บ้าง" ระบบตอบว่า
ไม่พบข้อมูล ทั้งที่เอกสารระบุรายชื่ออาชีพไว้ชัดเจนในหน้า 7

**สาเหตุ** คำถามมีชื่อหลักสูตรอยู่ด้วย ชื่อนั้นจึงครอบงำเวกเตอร์และไปจับคู่กับ chunk ทุกก้อนที่
เอ่ยชื่อเดียวกัน ซึ่งมีหลายร้อยก้อน รวมถึงภาคผนวกกว่าร้อยหน้าที่เป็นตารางประเมินความพึงพอใจ

**วิธีแก้** ระบุให้ได้ก่อนว่าคำถามถามถึงหลักสูตรใด แล้วจำกัดขอบเขตการค้นหาไว้ที่หลักสูตรนั้น
พร้อมตัดชื่อหลักสูตรออกจากข้อความค้นหา

| วิธีค้น | อันดับของ chunk ที่มีคำตอบ |
|---|---|
| ค้นทั้งคลัง ด้วยคำถามเต็ม | แย่กว่า 200 |
| ค้นเฉพาะเล่มนั้น ด้วยคำถามเต็ม | แย่กว่า 60 |
| ค้นเฉพาะเล่มนั้น ตัดชื่อหลักสูตรออก | **อันดับ 3** |

**ปัญหาที่ตามมา** เมื่อเพิ่มเงื่อนไขกรองหลักสูตร ระบบคืนผลลัพธ์ 0 รายการ ทั้งที่หลักสูตรนั้นมี
chunk อยู่ 422 ก้อน เนื่องจากดัชนี ivfflat เลือกรายการผู้สมัครจากดัชนีก่อนแล้วจึงกรองภายหลัง
**โดยไม่มีข้อความแจ้งข้อผิดพลาดใดๆ** แก้โดยปิดการใช้ดัชนีเฉพาะกรณีที่มีการกรอง

### 2.2 คำย่อที่ผู้ใช้จริงใช้

จากการทดสอบกับผู้ใช้ พบว่าผู้ใช้พิมพ์ "Comsci" ไม่ใช่ "วิทยาการคอมพิวเตอร์" ระบบจึงค้นไม่พบ
เพิ่มคำย่ออักษรโรมันเข้าตารางแปลง โดยเทียบแบบมีขอบเขตคำเพื่อไม่ให้ "it" ไปตรงกับตัวอักษร
กลางคำภาษาอังกฤษอื่น

### 2.3 ขอบเขตการตอบไม่ตรงกับที่กำหนดไว้

`docs/update.md` ระบุว่าคำถามเรื่องค่าเทอม กยศ. การรับสมัคร ต้องได้คำตอบว่า "ไม่พบข้อมูล
ในเอกสาร" พร้อมแนะนำหน่วยงานที่เกี่ยวข้อง แต่ระบบตอบว่า "ตอบได้เฉพาะเรื่องหลักสูตร"
ซึ่งสื่อผิด เพราะผู้ถามถามเรื่องมหาวิทยาลัยอยู่แล้ว

แก้โดยขยายเกณฑ์การคัดกรองให้ถือว่าทุกเรื่องที่เกี่ยวกับมหาวิทยาลัยอยู่ในขอบเขต แล้วให้
ขั้นตอนตรวจสอบเอกสารเป็นผู้ตัดสินว่ามีข้อมูลหรือไม่ พร้อมปรับข้อความให้ระบุหน่วยงานที่ควรติดต่อ

### 2.4 ความผิดพลาดที่ชุดประเมินตรวจพบก่อนส่งมอบ

ระหว่างแก้ปัญหาการค้นหารายวิชาบังคับ ได้ปรับให้ตัดคำห่อออกจากข้อความค้นหาทุกตำแหน่ง
ซึ่งแก้ปัญหาเดิมได้ แต่การรันชุดประเมินพบว่ากลุ่มคำถามเรื่องอาจารย์ **ตกจาก 2/2 เหลือ 0/2**

```
"ใครเป็นอาจารย์ผู้รับผิดชอบหลักสูตรวิทยาการคอมพิวเตอร์บ้าง"
        ↓ ตัดชื่อหลักสูตร + ตัดคำห่อทุกตำแหน่ง
"ใครเป็นอาจารย์ผู้รับผิดชอบ บ้าง"      ← ศัพท์เฉพาะขาด ค้นไม่เจอ
```

คำว่า "หลักสูตร" เป็นส่วนหนึ่งของศัพท์เฉพาะ "อาจารย์ผู้รับผิดชอบหลักสูตร" ที่ใช้ในเอกสาร มคอ.2
แก้โดยแยกคำห่อเป็นสองระดับ — ชื่อปริญญาและ "สาขาวิชา" ตัดได้ทุกตำแหน่ง ส่วน "หลักสูตร"
ตัดเฉพาะเมื่ออยู่ต้นประโยค

> **ข้อสังเกต** อาการของความผิดพลาดนี้ไม่ใช่ error แต่เป็นคำตอบว่า "ไม่พบข้อมูล" ซึ่งดูเหมือน
> ระบบทำงานปกติ หากไม่มีชุดประเมินที่รันซ้ำได้ ความผิดพลาดนี้จะถูกส่งมอบโดยไม่มีใครสังเกตเห็น

### 2.5 ผู้ใช้เห็นข้อความผิดพลาดทั้งที่ระบบทำงานปกติ

**อาการ** ผู้ใช้ถามคำถามแล้วได้ "เกิดข้อผิดพลาด กรุณาลองใหม่"

**สาเหตุ** คำถามเดียวกันตอบสำเร็จเมื่อทดสอบโดยตรง แต่ใช้เวลา 118 วินาที เพราะโมเดลถูกถอด
ออกจากหน่วยความจำการ์ดจอหลังไม่ถูกใช้ครบ 30 นาที ต้องโหลดกลับเข้าไปใหม่ ระหว่างนั้น
ตัวส่งต่อคำขอตัดการเชื่อมต่อทิ้ง และคืนหน้าเว็บแจ้งข้อผิดพลาดแทนข้อมูล JSON ทำให้ฝั่งหน้าเว็บ
อ่านรายละเอียดไม่ได้จึงแสดงข้อความสำรองที่ไม่บอกสาเหตุ

**วิธีแก้ 3 ชั้น**

| ชั้น | การแก้ไข |
|---|---|
| Backend | ยิงคำขอขนาดเล็กไปที่โมเดลทุก 20 นาที เพื่อไม่ให้ตัวนับ 30 นาทีหมดอายุ |
| API | ตอบรหัส 503 พร้อมข้อความอธิบายว่าโมเดลกำลังโหลด แทนรหัส 500 ที่ไม่บอกอะไร |
| หน้าเว็บ | แสดงข้อความว่าระบบกำลังเตรียมโมเดลและอาจใช้เวลาถึง 2 นาที |

### 2.6 ระบบเปิดไม่ขึ้นหลังรีสตาร์ทเครื่อง

**ปัญหาที่ 1 — ช่วงพอร์ตที่ Windows จองไว้** `uvicorn` ผูกพอร์ต 8000 ไม่ได้ แจ้งว่า
`[Errno 13] ... forbidden by its access permissions` ทั้งที่ไม่มีโปรแกรมใดใช้พอร์ตนั้น

สาเหตุคือ Windows จองช่วงพอร์ตให้ Hyper-V และ WSL ล่วงหน้า บนเครื่องที่ใช้พัฒนาช่วงที่จอง
คือ **7916–8715** ซึ่งคลุมทั้ง 8000 และ 8001 ช่วงนี้ถูกสุ่มใหม่ทุกครั้งที่รีสตาร์ทเครื่อง

ตรวจสอบด้วย `netsh interface ipv4 show excludedportrange protocol=tcp`
แก้โดยย้าย backend ไปใช้ **พอร์ต 9000** ซึ่งอยู่นอกช่วงที่จอง

**ปัญหาที่ 2 — โปรแกรมซ้ำซ้อนแย่งพอร์ต** ระบบแจ้งว่า `model "bge-m3" not found` ทั้งที่
โมเดลมีอยู่จริง เนื่องจาก Ollama ที่ติดตั้งบน Windows เริ่มทำงานอัตโนมัติเมื่อเปิดเครื่องและยึด
พอร์ต 11434 ก่อน โดยที่ตัวนั้นไม่มีโมเดลใดๆ (โมเดลอยู่ใน Docker volume)

แก้โดยหยุด Ollama บน Windows แล้วให้ container ยึดพอร์ตคืน
**ต้องปิดการเริ่มอัตโนมัติของ Ollama ใน Task Manager → Startup apps เพื่อไม่ให้เกิดซ้ำ**

## 4. สถานะระบบ ณ สิ้นรอบ

| ส่วน | สถานะ |
|---|---|
| ฐานข้อมูล | PostgreSQL 16.15 + pgvector 0.8.6 · 18 หลักสูตร · 7,301 chunk |
| โมเดล | qwen2.5:7b (ตอบคำถาม) + bge-m3 (embedding 1,024 มิติ) |
| Backend | พอร์ต **9000** พร้อม warmup อัตโนมัติทุก 20 นาที |
| Frontend | พอร์ต 3000 ส่งต่อ `/api/*` ไป backend |
| เวลาตอบ | คำทักทาย 0.1 วินาที · คำถามจากเอกสาร 6-21 วินาที |

**ลำดับการเปิดระบบ**

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d
```

```bash
cd backend; ..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 9000
```

```bash
cd frontend; npm run dev
```

ต้องเปิด Docker ก่อน backend เสมอ มิฉะนั้น backend จะค้างรอการเชื่อมต่อฐานข้อมูล

## 5. ข้อควรระวังก่อนสาธิต

1. **เปิดระบบล่วงหน้าอย่างน้อย 5 นาที** แล้วถามหนึ่งคำถามเพื่อให้โมเดลเข้าสู่หน่วยความจำ
   คำถามแรกหลังเปิดเซิร์ฟเวอร์ยังใช้เวลาประมาณ 100 วินาที
2. **อย่าให้ผู้ใช้หลายคนยิงคำถามพร้อมกัน** การ์ดจอ 8GB รองรับโมเดลสองตัวได้แบบไม่มีพื้นที่
   เหลือมาก การยิงติดกัน 17-22 ข้อทำให้ตัวรันโมเดลถูกฆ่ากลางคัน
3. **ตรวจว่า Ollama บน Windows ไม่ได้ทำงานอยู่** ก่อนเปิด container
4. **ตรวจว่าพอร์ต 9000 ยังใช้ได้** หลังรีสตาร์ทเครื่อง เพราะช่วงที่ Windows จองเปลี่ยนทุกครั้ง
