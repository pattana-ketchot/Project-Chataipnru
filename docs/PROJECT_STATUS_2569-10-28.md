## 1. ระบบทำอะไรได้แล้ว

### 1.1 หน้าเว็บ (ขึ้นใช้งานจริงแล้ว)

React + Vite · **14 หน้าสำหรับผู้ใช้ทั่วไป · 13 หน้าสำหรับผู้ดูแล**

| หน้า | ทำอะไร |
|---|---|
| หน้าแรก · หลักสูตรทั้งหมด · รายละเอียดหลักสูตร | ดูหลักสูตรทั้ง **14 หลักสูตร** · กรองตามระดับการศึกษา · ดูคุณสมบัติผู้สมัคร เอกสาร มคอ.2 คณาจารย์ อาชีพหลังจบ |
| ค้นหาสาขาที่เหมาะกับฉัน (4 ขั้น + หน้าผล) | ตอบแบบสอบถาม แล้วได้สาขาที่เหมาะ พร้อม**คำอธิบายเหตุผลที่ AI เขียน** |
| เปรียบเทียบสาขา + หน้าผล | เลือกได้ 2–4 สาขา เทียบ 7 หัวข้อจากเอกสาร มคอ.2 |

| ส่วนผู้ดูแล | เข้าสู่ระบบ · จัดการหลักสูตร ข่าว คลังความรู้ ผู้ใช้และสิทธิ์ · ตั้งค่า AI · ดูบันทึกการใช้งาน · เปลี่ยนรหัสผ่าน |

### 1.2 หลังบ้าน (ขึ้นใช้งานจริงแล้ว)

FastAPI · รันเป็น **7 คอนเทนเนอร์** โดยมี Caddy เป็นทางเข้าเดียวที่เปิดพอร์ต 80/443

| ส่วน | ทำอะไร |
|---|---|
| API ของหน้าเว็บ | ข้อมูลหลักสูตร · ข่าว · เปรียบเทียบ · แนะนำสาขา · แชท · อัปโหลดไฟล์ |
| บัญชีและสิทธิ์ | เข้าสู่ระบบด้วยโทเคน · แยกสิทธิ์ admin / editor · ล็อกบัญชีเมื่อกรอกผิดซ้ำ · เพิกถอนเซสชัน |
| สายงานเอกสาร | รับ PDF มคอ.2 → ตัดเป็นชิ้น → สร้างเวกเตอร์ → เก็บลงฐาน (ต้องมีคนอนุมัติก่อน) |
| ด่านตอบคำถาม | เรียงเป็นชั้น คำถามที่ฐานข้อมูลตอบได้จะไม่เรียกโมเดลเลย |

### 1.3 ฐานข้อมูล (ขึ้นใช้งานจริงแล้ว)

PostgreSQL + pgvector · **3 schema · 52 ตาราง · 10 วิว**

| schema | เก็บอะไร | ขนาดจริง |
|---|---|---|
| `public` | คลังเอกสาร มคอ.2 · ผู้ใช้ · บทสนทนา | **24 หลักสูตร · 31 ไฟล์ · 9,039 ชิ้นข้อมูล** (เวกเตอร์ 1024 มิติ) |
| `web` | ข้อมูลที่หน้าเว็บแสดง · ข่าว · คลังความรู้ · ตั้งค่า AI | **14 หลักสูตร** |
| `mko` | ข้อมูลหลักสูตรที่สกัดและ**ตรวจรับแล้ว** (หน่วยกิต รายวิชา คุณสมบัติ) พร้อมระบบเผยแพร่เป็นรุ่น | **5 ครั้งที่เผยแพร่** ล่าสุด 14 ต.ค. 2569 |

### 1.4 AI (ขึ้นใช้งานจริงแล้ว)

**ไม่ได้เทรนโมเดลเอง** ใช้โมเดลสำเร็จรูป งานที่ทำคือออกแบบระบบรอบโมเดลให้ตอบจากเอกสารจริงและตรวจย้อนได้

| หน้าที่ | โมเดลที่ใช้จริงบน production |
|---|---|
| สร้างเวกเตอร์ค้นเอกสาร | Ollama `bge-m3` (ในเครื่อง) |
| เขียนคำตอบ | Gemini `gemini-3.5-flash-lite` (`LLM_PROVIDER=gemini`) |
| สำรองเมื่อ Gemini ล่มก่อนพิมพ์ตัวแรก | Ollama `qwen2.5:3b` (ในเครื่อง) |

**กลไกที่ทำให้คำตอบตรวจสอบได้**

- เก็บเลขหน้าไว้กับทุกชิ้นข้อมูล คำตอบจึงอ้างชื่อไฟล์และหน้าได้
- หลังโมเดลเขียนคำตอบ มีขั้นตรวจว่าหน้าที่จะอ้าง**รองรับข้อความในคำตอบจริงหรือไม่** หน้าที่ไม่รองรับถูกตัดออก
- คำถามข้อเท็จจริงที่ `mko` ตอบได้ จะตอบจากฐานข้อมูลโดยไม่เรียกโมเดล — เร็วกว่าและไม่มีโอกาสแต่งข้อมูล
- เมื่อระบบไม่แน่ใจ จะบอกว่าไม่มีข้อมูลหรือถามกลับ แทนการเดา

### 2.2 วิธีทำงานที่ยึดตลอดโปรเจกต์

สามข้อนี้เป็นเหตุผลที่งานหลายรอบจับข้อผิดพลาดได้ก่อนขึ้น production

- **ยืนยันผล ไม่ใช่เส้นทาง** — ข้อตรวจต้องดูคำตอบจริงที่ผู้ใช้ได้ ไม่ใช่ดูว่าโค้ดเดินทางไหน
  (ชุดทดสอบของตัวเองเคยตกเพราะเขียนเกณฑ์แบบดูเส้นทาง แล้วแก้เกณฑ์ภายหลัง)
- **ซ้อนบนอิมเมจของ production ไม่ build จากที่ทำงานทั้งก้อน** — เพราะที่ทำงานมีงานค้าง
  ที่ยังไม่ผ่านการตรวจ รอบ 27 ต.ค. ต่างกัน **+388/−17 เทียบกับ +136/−9** ที่ปล่อยจริง
- **ตรวจด้วย SHA-256 ทุกขั้น** — ตั้งแต่ไฟล์ในชุด ไฟล์ในอิมเมจ ไฟล์ในคอนเทนเนอร์ที่รันจริง
  ไปจนถึงไฟล์ที่เว็บเสิร์ฟจริง (HTTP 200 ไม่ได้บอกว่าเนื้อไฟล์ถูก)

## 4. ผลทดสอบที่ยืนยันแล้ว และข้อจำกัด

### 4.1 สิ่งที่ยืนยันได้

| เรื่องที่ทดสอบ | ผลที่วัดได้ |
|---|---|
| แชทแยกหลักสูตรโท/เอกที่ชื่อสาขาเหมือนกัน | ถามระบุระดับ → ได้เล่มเดียวถูกระดับ · ถามไม่ระบุ → ถามกลับ ไม่เดา |
| ตอบระดับต่อเนื่องแล้วได้คำตอบจริง | บนเว็บ production: ตอบ "ปริญญาโท" → **36 หน่วยกิต** · "ปริญญาเอก" → **48 หน่วยกิต** พร้อมที่มา `agri68_master.pdf` / `agri68_phd.pdf` หน้า 6 · **วัดซ้ำระดับละ 2 ครั้ง ได้ผลเดิมทุกครั้ง** |
| เปรียบเทียบโท–เอก | 36 vs 48 หน่วยกิต · คุณสมบัติแยกถูกระดับ · ไม่ส่งระดับมา → 422 |
| เปลี่ยนเรื่องกลางบทสนทนา | ตอบคำถามใหม่ ไม่ถูกดึงกลับไปคำถามเดิม |
| ข้อมูลเดิมไม่ถูกเขียนทับ | ด่านตรวจในทรานแซกชันพบแถวที่คีย์อื่นเปลี่ยน **0 แถว** · หลัง deploy อาจารย์ 82 คน เอกสาร 24 ไฟล์ อาชีพ 110 รายการ ครบเท่าเดิม |
| rollback รักษางานผู้ดูแล | จำลองว่าผู้ดูแลแก้งานเพิ่มหลัง deploy แล้ว rollback — งานนั้นยังอยู่ · 10 แถวที่ไม่ถูกแตะ **sha256 ตรงกับไฟล์สำรองเป๊ะ** |
| ฐานที่ build หน้าเว็บตรงกับ production | **SHA-256 ของ bundle ตรงกันทุกไบต์** ทั้ง js และ css |
| ปล่อยเฉพาะที่ตั้งใจ | dry-run และ uptime ยืนยันว่าแตะเฉพาะ backend · ข้อมูลและหน้าเว็บ hash เดิม |

> เคยมีปัญหาและเรื่องที่แก้ในแต่ละรอบ ไม่ได้ครอบคลุมทุกเส้นทางของระบบ

- **ไม่ได้ยืนยันถ้อยคำของคำตอบที่โมเดลเขียน** ข้อตรวจทุกข้อวัดที่ขั้นที่ไม่มีโมเดลเกี่ยว
  (การเลือกเล่ม · การตีความคำถาม · คำตอบจากฐานข้อมูล) เพราะผลจากโมเดลไม่คงที่
  ถ้าจะยืนยันคุณภาพถ้อยคำ ต้องวัดเป็นอัตราจากหลายรอบ ไม่ใช่รอบเดียว
- **ไม่ได้ทดสอบโหลดหรือผู้ใช้พร้อมกันจำนวนมาก** — ยังยืนยันไม่ได้ว่ารองรับได้เท่าไร
- **ไม่ได้ทดสอบความปลอดภัยแบบเจาะระบบ** — มีแต่การตรวจสิทธิ์ในชุดทดสอบปกติ
- **ไม่ได้ทดสอบบนเบราว์เซอร์หลายรุ่นหลายอุปกรณ์** — ตรวจด้วยเบราว์เซอร์เดียว
  และตรวจขนาดจอมือถือ 375px ด้วยการวัดค่าจาก DOM
- **ความถูกต้องของข้อมูลหลักสูตรยืนยันได้เท่าที่ตรวจกับต้นทาง ณ 27 ต.ค. 2569**
  ถ้าเว็บคณะแก้ข้อมูลหลังจากนั้น ระบบจะไม่รู้ (ยังไม่มีระบบซิงก์อัตโนมัติ)
