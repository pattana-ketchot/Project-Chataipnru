## 2. Role `advisor_web` และวิธีทดสอบการเชื่อมต่อ

### 2.1 สถานะ role

advisor_web | login=true | superuser=false | createdb=false

### 2.2 สิทธิ์บน `public.users` — ถูกต้องตามออกแบบ

| ระดับ | สิทธิ์ |
|---|---|
| ระดับคอลัมน์ | `SELECT` บน **`id`, `is_active`, `supabase_user_id`** เท่านั้น |
| ระดับตาราง | **ไม่มีสิทธิ์ระดับตารางเลย** |
| อ่าน `email` | **ไม่ได้** — ไม่มี grant |
| `INSERT` / `UPDATE` / `DELETE` บน `users` | **ไม่มี** |

ตรงกับที่ M3 ออกแบบไว้ทุกประการ — ข้อห้าม "สร้างผู้ใช้ใหม่อัตโนมัติไม่ได้" และ "fallback ด้วย email ไม่ได้" **ถูกบังคับด้วยสิทธิ์ ไม่ใช่แค่ด้วยโค้ด**

### 2.3 ⚠ พบข้อควรแก้ — runbook เขียนสิทธิ์ของ role ไว้ไม่ครบ

ตรวจสิทธิ์ของ `advisor_web` **ทุกตาราง** ไม่ใช่เฉพาะ `users` พบว่า

| ตาราง | สิทธิ์ |
|---|---|
| `public.users` | ไม่มีสิทธิ์ระดับตาราง (มีเฉพาะ SELECT 3 คอลัมน์) |
| `ai_settings` | `SELECT`, `UPDATE` |
| `external_news` | `SELECT` |
| `knowledge_articles` | **`INSERT`, `SELECT`, `UPDATE`** |
| `news` | **`INSERT`, `SELECT`, `UPDATE`** |
| `site_courses` | **`INSERT`, `SELECT`, `UPDATE`** |

**Runbook หัวข้อ 1.4 เขียนว่า `INSERT / UPDATE / DELETE` → "ไม่มีสิทธิ์" โดยไม่ระบุว่าหมายถึงเฉพาะ `public.users`** ซึ่งอ่านแล้วเข้าใจได้ว่า role นี้เขียนอะไรไม่ได้เลย **ซึ่งไม่จริง**

| ประเด็น | ประเมิน |
|---|---|
| M3 ทำให้แย่ลงไหม | **ไม่** — สิทธิ์ชุดนี้มีอยู่ก่อนแล้วจากงาน web schema (ต้นเดือน ต.ค.) ไม่ได้เกิดจาก M3 |
| โค้ด M3 เขียนตารางพวกนี้ไหม | **ไม่** — `db.mjs` รันเฉพาะ `RESOLVER_SQL` ซึ่งเป็น `SELECT` บน `public.users` |
| เป็น blocker ไหม | **ไม่ใช่** |
| ต้องทำอะไร | แก้ข้อความใน runbook ให้ระบุขอบเขตให้ชัด · และพิจารณาภายหลังว่าควรแยก role อ่านอย่างเดียวสำหรับ M3 โดยเฉพาะหรือไม่ |

> เขียนไว้ตรงนี้เพื่อให้คนที่อ่าน runbook ตอน deploy ไม่เข้าใจผิดว่าถ้าโค้ดพลาดแล้วจะเขียนอะไรไม่ได้เลย

### 2.4 วิธีทดสอบการเชื่อมต่อจริง — ตรวจแล้วว่าไม่เปิดเผยรหัสผ่าน

Runbook หัวข้อ 4.0 ให้รันในคอนเทนเนอร์ `webapi` แล้วเรียก resolver ด้วย UUID ที่เป็นศูนย์ทั้งหมด

| ข้อกังวล | ตรวจแล้ว |
|---|---|
| แสดงรหัสผ่านไหม | **ไม่** — `describeConnection()` คืนแค่ `user@host:port/database` และ `createDatabase()` ตั้ง `config.password` เป็น `undefined` |
| เปลี่ยนรหัสผ่านไหม | **ไม่** — ไม่มี `ALTER ROLE` อยู่ที่ใดในเอกสารทั้งชุด |
| เขียนฐานข้อมูลไหม | **ไม่** — `RESOLVER_SQL` เป็น `SELECT` ล้วน |
| ใช้ UUID ของคนจริงไหม | **ไม่** — ใช้ค่าศูนย์ทั้งหมดที่ไม่มีอยู่จริง |
| หลง `trust` ของ `pg_hba` ไหม | **ไม่** — ต่อจากคอนเทนเนอร์ `webapi` ผ่าน network ไปที่ host `postgres` ไม่ใช่ `127.0.0.1` |

**เกณฑ์ตัดสิน** — ได้ `ACCOUNT_NOT_LINKED` + `status: up` คือผ่าน · ได้ `IDENTITY_LOOKUP_FAILED` + `status: down` คือไม่ผ่าน
