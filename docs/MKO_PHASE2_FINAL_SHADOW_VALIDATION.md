## B. Semantics ของ structured admission

**สิ่งที่ structured ตอบจริง:** รายการจากหัวข้อ "คุณสมบัติของผู้เข้าศึกษา" ของ มคอ.2 ฉบับนั้นเท่านั้น (tqf2 หมวด 3 ข้อ 2.2 · std2565 หมวด 6 ข้อ 1) — **ไม่ใช่เกณฑ์รับสมัครล่าสุดของมหาวิทยาลัย** และไม่ได้รวมหัวข้ออื่นใน มคอ.2 ที่เกี่ยวกับการรับเข้า

**รูปแบบคำตอบปัจจุบัน** (จาก `mko.shadow_answers.structured_answer`):

```
คุณสมบัติของผู้เข้าศึกษา ตามหลักสูตรการแพทย์แผนไทยประยุกต์บัณฑิต (พ.ศ. 2565)
1. จะต้องเป็นผู้สำเร็จการศึกษาระดับมัธยมศึกษาตอนปลายและศึกษากลุ่มสาระการเรียนรู้ ทางวิทยาศาสตร์-คณิตศาสตร์ ผลการเรียนเฉลี่ยไม่น้อยกว่า 2.50 …
ที่มา: attm65.pdf หน้า 19
```

| คำถาม | ประเมิน |
|---|---|
| บอกหลักสูตรและปีฉบับ | ✔ ชัด "(พ.ศ. 2565)" |
| บอกไฟล์และหน้า | ✔ "attm65.pdf หน้า 19" — แต่ชื่อไฟล์ไม่มีความหมายสำหรับผู้ใช้ |
| บอกว่าเป็นหัวข้อหนึ่งของ มคอ.2 | ✘ ไม่บอก |
| บอกว่าไม่ใช่ประกาศรับสมัครประจำปี | ✘ ไม่บอก |
| ครบตามเอกสารฉบับเดียวกัน | ✘ **attm65: ขาดอายุไม่เกิน 25 ปี / GPAX 5 ภาค / GAT-PAT ที่เล่มเดียวกันระบุไว้** · ไม่รวมข้อบังคับมหาวิทยาลัยและข้อภาษาไทย |

**ผลเชิงผู้ใช้:** หัวข้อ "คุณสมบัติของผู้เข้าศึกษา" พร้อมรายการ อ่านได้ว่าเป็นเงื่อนไขครบถ้วนในการสมัคร ผู้ใช้ที่ถามหลักสูตรแพทย์แผนไทย 2565 จะไม่รู้ว่ามีเกณฑ์อายุและ GPAX ซึ่งเอกสารฉบับเดียวกันระบุ — **ข้อมูลไม่ผิด แต่ provenance / ขอบเขตไม่ชัดพอและทำให้เข้าใจผิดโดยการละเว้นได้อย่างมีนัยสำคัญ** → **BLOCKER สำหรับ admission ใน user-facing** (ไม่ได้แก้ prompt / wording ในรอบนี้ตามที่สั่ง)

ข้อสังเกตเพิ่ม: ข้อมูลของหลายหลักสูตรเป็น มคอ.2 ปี 2561–2568 เกณฑ์รับสมัครจริงของปีปัจจุบันอาจต่างไป — เป็นอีกเหตุผลที่คำตอบต้องบอกขอบเขต

**ทางเลือกที่เล็กที่สุดสำหรับ admission** (ไม่เสนอ P4 · ไม่ redesign)

2. **(ทางเลือก) แก้ wording ของ admission จุดเดียว** — หัวข้อเป็น "คุณสมบัติของผู้เข้าศึกษาตามหัวข้อใน มคอ.2 ฉบับ พ.ศ. X (เกณฑ์รับสมัครประจำปีเป็นไปตามประกาศรับสมัครของมหาวิทยาลัย)" — แก้ความเข้าใจเรื่อง "ประกาศประจำปี" ได้ แต่ **ไม่แก้กรณีละเว้นเกณฑ์ในเล่มเดียวกัน** (attm65) จึงยังต้องยอมรับ limitation นี้หรือยกเว้น attm65

## F. Go / No-Go

1. **มี blocker จริงหรือไม่**
   **มี 1 ข้อ เฉพาะ admission ในโหมด user-facing** — provenance/ขอบเขตของคำตอบทำให้เข้าใจผิดโดยการละเว้นได้ (ข้อ B) · **ไม่พบ blocker ด้านความถูกต้องของข้อมูลหรือการเลือกหลักสูตร/ฉบับ/ระดับ** ในทุก field

2. **field ที่พร้อม user-facing:** total_credits · edition_year · careers (with limitation) · objectives (with limitation)

3. **field ที่ยังไม่พร้อม:** admission

4. **admission discrepancy มาจากไหน**
   คำตอบ RAG ใช้ chunk จาก มคอ.2 **เล่มเดียวกัน** แต่คนละหัวข้อ: หัวข้อการรับนักศึกษา (attm65 หน้า 105: อายุ/GPAX/GAT-PAT), ข้อการรับเข้าศึกษาด้านภาษาไทย (it66 หน้า 6), ภาคผนวกข้อบังคับมหาวิทยาลัย (bio2568 หน้า 201, it66 หน้า 161, attm65 หน้า 137: โทษจำคุก/ความประพฤติ/โรค) — ส่วน structured สกัดเฉพาะหัวข้อ "คุณสมบัติของผู้เข้าศึกษา" · ข้อความที่ไม่มีหลักฐานมีเพียง "(สำหรับหลักสูตรต่อเนื่อง)" ของ IT และคำสะกดผิด "สาชา"

5. **จำเป็นต้องแก้ code ก่อน ON หรือไม่**
   **จำเป็น** — ด้วยเหตุผลที่ไม่เกี่ยวกับ blocker ข้างต้น: โค้ดปัจจุบันไม่มีเส้นทางตอบผู้ใช้ด้วย structured เลย `configured_mode("on")` บังคับกลับเป็น shadow ([structured_shadow.py:77-85](backend/app/services/structured_shadow.py:77)) การตั้ง `STRUCTURED_ANSWERS=on` จึงไม่เปลี่ยนคำตอบผู้ใช้ ต้องมีงาน implement เส้นทางตอบ (ซึ่งเป็นขอบเขต Phase 3 และต้องอนุมัติแยก)
   สำหรับ admission blocker **ไม่ต้องแก้ข้อมูลหรือ review** ถ้าเลือกทางเลือก 1

6. **Minimal fix ที่จำเป็น (ถ้าอนุมัติให้ทำ)**
   - เส้นทางตอบผู้ใช้เมื่อ `on`: ใช้ `structured_answer` เฉพาะเมื่อ route = structured, status = answered และ field อยู่ในรายการที่อนุญาต **{total_credits, edition_year, careers, objectives}** — กรณีอื่นทั้งหมด (no_data, rag, admission) ใช้คำตอบ RAG เดิม และยังบันทึก shadow ต่อ
   - ไม่ต้องแก้ extraction / schema / routing / comparator / prompt ของ RAG

7. **Controlled ON rollout plan (เสนอเท่านั้น — ไม่ได้เปิดเอง)**
   0. ตัดสินก่อน: known issue en65 careers "น้ า" (ยอมรับ หรือ supersede decision + publish ใหม่แยกรอบ)
   1. implement เส้นทางตอบตามข้อ 6 + field allow-list ที่ปิด admission ไว้ + ทดสอบ offline (ชุด suite เดิม + กรณี on/off/shadow และ no_data → RAG) — ขออนุมัติแยก
   2. deploy แบบ controlled (backup, rollback image, flag ยังเป็น shadow) → ตรวจ health
   3. เปลี่ยน flag เป็น `on` (restart backend เท่านั้น) · rollback = ตั้งกลับเป็น `shadow` แล้ว restart
   4. ทดสอบเล็ก ≤ 10 คำขอ: total_credits ตรี/โท/เอก · edition_year หลายฉบับ · careers · objectives · admission (ต้องยังเป็น RAG) · no_data control · follow-up year swap · ชื่อสาขาหลายระดับที่ไม่ระบุระดับ (ต้องเป็น RAG)
   5. เฝ้าดู `mko.shadow_answers` + log 24–48 ชั่วโมง เกณฑ์ย้อนกลับ: structured ตอบผิดหลักสูตร/ฉบับ/ระดับ หรือ error ใหม่
   6. admission: พิจารณาเปิดภายหลังเมื่อผู้อนุมัติเลือกทางเลือก 2 หรือแนวทางอื่นที่แก้การละเว้นได้
