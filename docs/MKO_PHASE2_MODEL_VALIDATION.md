### เคส 1 — "สาขาวิทยาการคอมพิวเตอร์เรียนกี่หน่วยกิต" → "แล้วคณิตศาสตร์ล่ะ" (1 รอบ) — **PASS** (มีข้อสังเกตเรื่องคุณภาพคำตอบ)

| | |
|---|---|
| interpreted_question | `สาขาคณิตศาสตร์เรียนกี่หน่วยกิต` (ประกอบด้วยโค้ด ไม่เรียก condense) |
| programmes/scopes | `คณิตศาสตร์` · structured intent: total_credits / คณิตศาสตร์ |
| grounding | true — "เนื้อหามีข้อมูลระบุจำนวนหน่วยกิตรวมตลอดหลักสูตรของสาขาวิชาคณิตศาสตร์ เช่น ไม่น้อยกว่า 124 หรือ 130 หน่วยกิต ตามหลักสูตร พ.ศ. 2564 และ พ.ศ. 2569" |
| คำตอบ Gemini | "หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาคณิตศาสตร์ (Bachelor of Science Program in Mathematics) มีจำนวนหน่วยกิตรวมตลอดหลักสูตรไม่น้อยกว่า 124 ถึง 130 หน่วยกิต ตามแผนของแต่ละปีพุทธศักราชหลักสูตร" |

- **เหตุผล:** ตีความเป็นหลักสูตรคณิตศาสตร์ + total_credits ไม่ใช่รายวิชาคณิตศาสตร์ใน CS (ก่อนแก้ได้ "สาขาวิทยาการคอมพิวเตอร์เรียนวิชาคณิตศาสตร์อะไรบ้าง")
- **ข้อสังเกต:** คำตอบรวมสองฉบับเป็นช่วง "124 ถึง 130" โดยไม่บอกว่าเลขใดเป็นของปีใด
  - ตัวเลขทั้งสองมีในเอกสารจริง (2569 = 124, 2564 = 130) จึงไม่ใช่การแต่งข้อมูล แต่ไม่เจาะจงพอ
  - เป็นพฤติกรรมของคำตอบหลักสูตรเดียวแบบเดิม (production เคยตอบถ้อยคำเดียวกันก่อนแก้) รอบนี้ไม่ได้แก้ส่วนนี้

|---|---|

**รอบที่ 1**
- **คำตอบ:** เทียบปรัชญาของสองหลักสูตร (2566) และโครงสร้าง: หน่วยกิตรวม 130 เท่ากัน, ศึกษาทั่วไป 30 / เฉพาะ 94 / เลือกเสรี 6, CS มีกลุ่มวิชาแกน 18 + เฉพาะด้าน 54, IT มีกลุ่มวิชาแกน 15 + เฉพาะด้าน 57 และปิดว่า "อาชีพ…มีความแตกต่างกันตามตำแหน่งงานที่ระบุไว้ในเอกสาร"
- **ตรวจกับหลักฐาน:** ทุกตัวเลขอยู่ในหน้า 1 ของ CS 2566 และ IT 2566 ตรงกับหลักสูตรที่อ้าง ถ้อยคำปรัชญาตรงกับเอกสาร ("หน่วยงานภาครัฐ ภาคเอกชน และชุมชน", "ตอบสนองแรงงานในยุคดิจิทัล")
- **ข้อสังเกต:** ประโยคเรื่องอาชีพกว้างเกินไป ไม่ได้ยกตำแหน่งงาน แต่ไม่ได้แต่งข้อมูล

**รอบที่ 2**
- **คำตอบ:** เทียบเฉพาะปรัชญาของสองหลักสูตร (2566) ถ้อยคำตรงกับเอกสาร
- **ข้อสังเกต:** ถูกต้องแต่ใช้หลักฐานน้อยกว่าที่มี (ไม่ใช้โครงสร้าง/อาชีพ)

**เหตุผล PASS:** เปรียบเทียบจากหลักฐานของทั้งสองหลักสูตรทั้งสองรอบ ไม่พบข้อมูลนอกเอกสาร ระบุปีฉบับ

**คำตอบ (ทั้งสองรอบ รูปแบบเดียวกัน)** เป็นหัวข้อย่อยตามด้าน และกำกับปีทุกข้อ
- **ปรัชญา:** แอนิเมชันฯ (พ.ศ. 2569) / CS (พ.ศ. 2566)
- **วัตถุประสงค์:** แอนิเมชันฯ เน้นแอนิเมชัน เกม สื่อดิจิทัล เครื่องมือเฉพาะทาง (2569) / CS เน้นแก้ปัญหาทางคอมพิวเตอร์ ตอบสนองชุมชน ภาครัฐ เอกชน (2566)

- "แก้ไขปัญหาทางคอมพิวเตอร์" มาจากวัตถุประสงค์ของ CS 2566 หน้า 1

- ใช้ด้านที่เทียบกันได้ และกำกับปีต่างฉบับถูกต้อง (2569 กับ 2566)
- ไม่ได้ใช้อาชีพฉบับ 2564 ในคำตอบ จึงไม่มีกรณีปนปีโดยไม่ระบุ

- **grounding:** true — "…เนื้อหามีข้อมูลรายวิชาและโครงสร้างของทั้งสองหลักสูตร ซึ่งผู้ตอบสามารถยกข้อมูลมาประกอบและระบุได้ว่ายังไม่สามารถสรุปเชิงปริมาณได้ชัดเจนจากข้อมูลที่มี"
- **คำตอบ:** "ยังสรุปจากเอกสารที่มีไม่ได้ เพราะเนื้อหาไม่ได้เปรียบเทียบจำนวนวิชาหรือหน่วยกิตด้านการเขียนโปรแกรมของทั้งสองหลักสูตรไว้โดยตรง ทั้งนี้ หลักสูตร…วิทยาการคอมพิวเตอร์… พ.ศ. 2566 มีกลุ่มเทคโนโลยีและวิธีการทางซอฟต์แวร์ 24 หน่วยกิต ส่วนหลักสูตร…เทคโนโลยีสารสนเทศ… พ.ศ. 2566 มีกลุ่มเทคโนโลยีและวิธีการทางด้านซอฟต์แวร์ 15 หน่วยกิต การตัดสินต้องกำหนดเกณฑ์เปรียบเทียบเพิ่มเติม เช่น จำนวนรายวิชาและเนื้อหาเจาะลึกด้านการเขียนโปรแกรมในหลักสูตรฉบับเต็ม"
- **ตรวจกับหลักฐาน:** CS 2566 กลุ่มเทคโนโลยีและวิธีการทางซอฟต์แวร์ 24 หน่วยกิต (cs66.pdf หน้า 12 โครงสร้างหลักสูตร และหน้า 16/40) · IT 2566 กลุ่มเดียวกัน 15 หน่วยกิต (หน้า 1 และ 20) — ถูกต้อง
- **เหตุผล PASS:** บอกก่อนว่ายังสรุปไม่ได้ ไม่ฟันธง แสดงข้อมูลของทั้งสองหลักสูตร และบอกว่าต้องกำหนดเกณฑ์
- **ข้อสังเกต:**
  - ยกตัวเลขกลุ่มวิชาซอฟต์แวร์ 24 กับ 15 วางคู่กันโดยไม่ได้บอกว่ากลุ่มนี้ไม่เท่ากับ "วิชาเขียนโปรแกรมทั้งหมด" ผู้อ่านอาจตีความเป็นคำตอบโดยนัยได้
  - ไม่ได้ยกชื่อรายวิชาเขียนโปรแกรมตัวอย่าง
  - เกณฑ์ที่บอกไม่ครบตามกฎ (ไม่พูดถึงวิชาบังคับ/เลือกและปีหลักสูตร)

**ปัญหาที่พบ (รายงานเท่านั้น ไม่ได้แก้ในรอบนี้)**
1. **ด่านตรวจของคำถามเปรียบเทียบเชิงปริมาณยังไม่นิ่ง:** หลักฐานชุดเดียวกันทุกชิ้น ได้ false 1 รอบและ true 1 รอบ (temperature 0) รอบที่ false ทำให้ผู้ใช้ได้ "ไม่พบข้อมูล" แบบเดิม ข้อมูลที่ตอบได้หายไปทั้งหมด
2. **คำตอบเชิงปริมาณยังไม่ครบตามกฎ:** ไม่ยกรายวิชาตัวอย่าง บอกเกณฑ์ไม่ครบ และวางตัวเลขกลุ่มวิชาคู่กันโดยไม่บอกข้อจำกัดของตัวเลขนั้น
3. **ความลึกของคำตอบเปรียบเทียบไม่คงที่:** เคส 4 รอบ 2 ใช้แค่ด้านปรัชญา ทั้งที่มีหลักฐานครบ 4 ด้าน
4. **คำตอบหลักสูตรเดียวที่มีหลายฉบับรวมตัวเลขเป็นช่วงโดยไม่ระบุปี (เคส 1):** เป็นพฤติกรรมเดิม ไม่ใช่ผลของการแก้รอบนี้

**ข้อจำกัดของการทดสอบ**
- แต่ละเคสมี 1–2 รอบ ใช้ประมาณอัตราไม่ได้ ตัวอย่างเช่นผลของเคส 6 อาจแกว่งมากหรือน้อยกว่าที่เห็น
- ใช้ฐานข้อมูลและ embedding ในเครื่องที่ตรงกับ production ไม่ได้ผ่านเว็บจริง

## 4. ความพร้อมสำหรับ controlled shadow deployment

**ข้อเท็จจริงที่ต้องตัดสินใจก่อน:** โค้ด stabilization **ไม่ใช่การเปลี่ยนแบบ shadow** ถ้า deploy คำตอบที่ผู้ใช้เห็นจะเปลี่ยนทันทีใน 3 เรื่องนี้ ไม่ว่า `STRUCTURED_ANSWERS` จะเป็นค่าใด
- การตีความคำถามต่อเนื่อง
- หลักฐานและกฎของคำถามเปรียบเทียบ
- แคชหมดอายุหนึ่งครั้ง

**ความเห็น**
- **Follow-up (เคส 1–3):** พร้อม — กำหนดได้ด้วยโค้ด ผลคงที่ และถูกทุกเคส
- **คำถามเปรียบเทียบทั่วไป (เคส 4–5):** ดีขึ้นชัดเจนเทียบกับ production ปัจจุบัน ซึ่งเคยปฏิเสธเคส 5 ไม่พบการแต่งข้อมูล
- **คำถามเปรียบเทียบเชิงปริมาณ (เคส 6):** ยังไม่นิ่ง แต่กรณีแย่ที่สุดที่เห็นคือ "ไม่พบข้อมูล" ซึ่งเท่ากับพฤติกรรมของ production ตอนนี้ **ไม่แย่กว่าเดิม** ส่วนกรณีดีได้คำตอบที่ถูกและไม่ฟันธง
- **สรุป:** ไม่พบเหตุด้านความถูกต้องของข้อมูลที่ต้องห้าม deploy แบบควบคุม แต่ **ยังไม่ผ่านเกณฑ์ข้อ 6 ครบทุกรอบ** การตัดสินใจเป็นของผู้อนุมัติ ทางเลือกคือ
  - (ก) deploy แบบควบคุม โดยยอมรับว่าเคสเชิงปริมาณยังแกว่ง แล้ววัดต่อจาก shadow/ผลใช้งานจริง
  - (ข) แก้ความไม่นิ่งของด่านตรวจเชิงปริมาณก่อน แล้ววัดซ้ำด้วยจำนวนรอบที่มากพอจะบอกเป็นอัตรา

ยังไม่ได้ทำอะไรต่อ — รออนุมัติ
