# คู่มือเรียกใช้ API สำหรับคนทำหน้าเว็บ

ระบบหลังบ้านเปิดใช้งานจริงแล้ว ต่อได้เลยไม่ต้องติดตั้งอะไรในเครื่อง

**ที่อยู่**: `http://161.118.237.37/api`

ตัวอย่างทั้งหมดในเอกสารนี้เป็นคำขอและคำตอบที่ยิงกับเซิร์ฟเวอร์จริง ไม่ใช่ตัวอย่างสมมติ

---

## กฎสองข้อที่ต้องรู้ก่อนเขียนโค้ด

**1. เรียกด้วย path สัมพัทธ์ `/api/*` เสมอ อย่าใส่ที่อยู่เต็ม**

```js
fetch("/api/match", ...)                      // ถูก
fetch("http://161.118.237.37/api/match", ...) // ผิด
```

ถ้าใส่ที่อยู่เต็มจะติด CORS และเวลาย้ายเซิร์ฟเวอร์ต้องแก้โค้ดทุกจุด การใช้ path สัมพัทธ์
ทำให้เบราว์เซอร์เห็นเป็น origin เดียวกับหน้าเว็บ

**2. ทุก endpoint ยกเว้น `/courses` ต้องแนบ token**

---

## ขั้นที่ 1 — สมัครสมาชิกและเข้าสู่ระบบ

```
POST /api/auth/register     { "email": "...", "password": "..." }   รหัสผ่านอย่างน้อย 8 ตัว
POST /api/auth/login        { "email": "...", "password": "..." }
```

`/auth/login` คืน

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...",
  "token_type": "bearer"
}
```

เก็บ `access_token` ไว้แล้วแนบไปกับทุกคำขอ

```js
headers: { Authorization: `Bearer ${accessToken}` }
```

> **ข้อควรระวัง** token หมดอายุใน 30 นาที และตอนนี้**ยังไม่มี endpoint ต่ออายุ**
> ถ้าเจอ 401 ให้พาผู้ใช้ไปเข้าสู่ระบบใหม่ ถ้าต้องการให้ต่ออายุอัตโนมัติบอกได้ เดี๋ยวเพิ่มให้

## ขั้นที่ 2 — ค้นหาสาขาที่เหมาะกับคุณ

```
POST /api/match
```

ส่งคำตอบทั้ง 5 ขั้นมาในคำขอเดียว **ไม่ต้องบันทึกโปรไฟล์ก่อน** และไม่ต้องตอบครบทุกช่อง

| ช่อง | ชนิด | ตรงกับขั้นตอนไหน |
|---|---|---|
| `study_track` | ข้อความ | ขั้น 1 สายการเรียน |
| `favorite_subjects` | รายการข้อความ | ขั้น 1 วิชาที่ชอบ |
| `interests` | รายการข้อความ | ขั้น 2 ความสนใจ |
| `aptitudes` | รายการข้อความ | ขั้น 3 ความถนัด |
| `career_goal` | รายการข้อความ | ขั้น 4 เป้าหมายอาชีพ |
| `work_environment` | รายการข้อความ | ขั้น 4 สภาพแวดล้อมการทำงาน |
| `extra` | ข้อความ | ช่องพิมพ์อิสระ (ถ้ามี) |
| `limit` | ตัวเลข 1–10 | จำนวนผลลัพธ์ ค่าเริ่มต้น 5 |

**ส่งข้อความตามที่แสดงบนปุ่มได้เลย** ไม่ต้องแปลงเป็นรหัส ระบบเข้าใจภาษาไทยธรรมดา

```js
const res = await fetch("/api/match", {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${token}` },
  body: JSON.stringify({
    study_track: "วิทย์-คณิต",
    favorite_subjects: ["คอมพิวเตอร์", "คณิตศาสตร์"],
    interests: ["เทคโนโลยีและคอมพิวเตอร์"],
    aptitudes: ["ชอบเขียนโค้ด พัฒนาโปรแกรม และแก้บั๊ก"],
    career_goal: ["ทำงานในองค์กรขนาดใหญ่"],
    work_environment: ["ทำงานในออฟฟิศ"],
    limit: 4,
  }),
});
const data = await res.json();
```

**คำตอบที่ได้จริง** (ตัดให้เหลือ 2 รายการเพื่อความสั้น)

```json
{
  "profile_text": "เรียนสายวิทย์-คณิต ชอบวิชา คอมพิวเตอร์, คณิตศาสตร์ สนใจด้าน เทคโนโลยีและคอมพิวเตอร์ ถนัด ชอบเขียนโค้ด พัฒนาโปรแกรม และแก้บั๊ก เป้าหมายอาชีพคือ ทำงานในองค์กรขนาดใหญ่ อยากทำงานแบบ ทำงานในออฟฟิศ",
  "model_used": "gemini-3.5-flash-lite",
  "matches": [
    {
      "course_id": "34c21266-4e5a-407c-8e77-fc95d7c94fe1",
      "title": "หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาวิทยาการคอมพิวเตอร์ (พ.ศ. 2561)",
      "score": 0.5545,
      "match_percent": 55,
      "rationale": "หลักสูตรนี้มีความสอดคล้องกับความสนใจด้านเทคโนโลยีและคอมพิวเตอร์ รวมถึงเป้าหมายอาชีพนักเขียนโปรแกรมที่ตรงกับสิ่งที่นักเรียนมีความถนัดในการเขียนโค้ดและพัฒนาโปรแกรม",
      "evidence_chunk_ids": ["b6950dd5-d8ae-4f2c-97b1-db0a84e3ada2"]
    },
    {
      "course_id": "2fa6627f-e2fa-4956-b9d0-d0c82ad3dcaf",
      "title": "หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาเทคโนโลยีสารสนเทศ (พ.ศ. 2566)",
      "score": 0.5448,
      "match_percent": 53,
      "rationale": "ข้อมูลในหลักสูตรระบุถึงความต้องการพัฒนาทักษะด้านการเขียนโปรแกรมและการพัฒนาซอฟต์แวร์ ซึ่งตรงกับความถนัดและความชอบในการเขียนโค้ดและพัฒนาโปรแกรมของนักเรียน"
    }

```

**เอาไปแสดงยังไง**

| ฟิลด์ | ใช้ทำอะไร |
|---|---|
| `title` | ชื่อบนการ์ด — ตัด `หลักสูตร...สาขาวิชา` ออกได้ถ้าอยากให้สั้น |
| `match_percent` | ตัวเลข % และความยาวแถบ |
| `rationale` | ข้อความอธิบายใต้ชื่อ |
| `course_id` | ใช้กับปุ่ม "ดูรายละเอียด" → `GET /api/courses/{course_id}` |
| `score` | ค่าดิบ ไม่ต้องแสดง เก็บไว้ตรวจสอบ |
| `profile_text` | ข้อความที่ระบบเข้าใจ มีประโยชน์ตอนดีบัก |

> **`match_percent` คืออะไร** เป็นความใกล้เคียงเชิงความหมายระหว่างคำตอบของนักเรียน
> กับเนื้อหาและชื่อหลักสูตร คำนวณจากเวกเตอร์จริงและถามซ้ำได้ค่าเดิมเสมอ
>
> **ไม่ใช่** ความน่าจะเป็นที่จะเรียนจบหรือคะแนนความเหมาะสมที่พิสูจน์แล้ว
> ควรมีข้อความกำกับใต้ตัวเลขสักบรรทัด เช่น *"คำนวณจากความสอดคล้องระหว่างคำตอบของคุณ
> กับเนื้อหาหลักสูตร"* เพราะตัวเลขเปอร์เซ็นต์ทำให้คนเข้าใจว่าแม่นกว่าความเป็นจริง

**ความแม่นที่วัดได้** ทดสอบด้วยโปรไฟล์ 8 ชุดที่รู้คำตอบล่วงหน้า — อันดับ 1 ถูก 6/8 และ
ติด 3 อันดับแรก 7/8 **ควรแสดงผลหลายรายการให้ผู้ใช้เลือกเอง อย่าแสดงแค่อันดับ 1**

## ขั้นที่ 3 — รายการหลักสูตร

```
GET /api/courses               ไม่ต้องใช้ token
GET /api/courses/{course_id}   ไม่ต้องใช้ token
```

ใช้กับหน้า "หลักสูตรทั้งหมด" และปุ่มดูรายละเอียดจากหน้าผลลัพธ์

## ขั้นที่ 4 — แชทกับที่ปรึกษา

มีสองแบบ **หน้าเว็บควรใช้แบบสตรีม**

```
POST /api/chat          รอจนเขียนเสร็จแล้วส่งทีเดียว
POST /api/chat/stream   ทยอยส่งทีละส่วน
```

ทั้งคู่รับ `{ "message": "...", "session_id": null }` ส่ง `session_id` ที่ได้กลับมาในครั้งถัดไป
เพื่อคุยต่อในบทสนทนาเดิม

**อย่าใช้ `await response.json()` กับ `/chat/stream`** เพราะคำตอบทยอยมาทีละส่วน ถ้ารอ
ทั้งก้อนจะเสียข้อดีไปหมด — โค้ดที่ใช้ได้จริงอยู่ในฟังก์ชัน `chatStream` ที่
`frontend/lib/api.ts` ลอกไปใช้ได้เลย

รูปแบบข้อมูลที่ทยอยมา (Server-Sent Events)

```
event: meta      ข้อมูลสรุป — session_id, status, รายการอ้างอิง  (มาก่อนตัวอักษรแรก)
event: token     ข้อความส่วนถัดไป {"t":"..."}                     (มาหลายครั้ง)
event: done      จบแล้ว
event: error     เกิดข้อผิดพลาด {"detail":"..."}
```

`status` ใน `meta` บอกว่าระบบตัดสินอย่างไร ใช้ตกแต่งหน้าจอได้

| ค่า | ความหมาย | ควรแสดงอย่างไร |
|---|---|---|
| `answered` | ตอบจากเอกสารจริง | แสดงปุ่มดูรายการอ้างอิง |
| `not_found` | อยู่ในเรื่องแต่เอกสารไม่มีข้อมูล | ไม่ต้องแสดงรายการอ้างอิง |
| `out_of_scope` | นอกขอบเขต | ไม่ต้องแสดงรายการอ้างอิง |
| `small_talk` | ทักทาย | ไม่ต้องแสดงรายการอ้างอิง |

## สิ่งที่ยังไม่มี บอกได้ถ้าต้องการ

| เมนูในแบบร่าง | สถานะ |
|---|---|
| เปรียบเทียบสาขา | ยังไม่มี endpoint |
| อาชีพหลังจบ (หน้าแยก) | ยังไม่มี แต่ถามผ่านแชทได้แล้ว |
| ต่ออายุ token อัตโนมัติ | ยังไม่มี |
